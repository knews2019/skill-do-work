- [family: closed-enumeration-for-a-condition] [REQ-460](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-081/REQ-460-make-outside-text-delimiter-containment-condition-complete.md#lessons-learned): when a contract states a condition, testing membership in a list of examples is a different contract that happens to agree on the examples — `summaryRequiresContainment` recognized ten prefixes and inlined `***`, `___`, `+++`, `:::note`, `$$`, `===`, bare `-`/`*`/`+`, bare `1.`, pipe tables and indented code. **A partially-correct enumeration is worse than an empty one**: `---` and `* * *` were caught while `***` and `___` were not, so the class looked handled. Two traps worth carrying: a trim that runs *before* the test can destroy the very bytes that constitute the structure (`TrimLeft(" \t")` made indented code unreachable), and a widening like this is only provable as safe by differential — 160,906 inputs, old predicate against new, 0 weakenings, which no fixture set establishes. - [family: single-exit-owner] [REQ-525](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-085/REQ-525-block-the-install-confirmation-before-signalling-it.md#lessons-learned): **two goroutines that can both reach `os.Exit` have no correct ordering** — whichever gets there first decides the status. A signal handler doing `os.Exit(130)` raced the ordinary return path, and because a cancelled confirmation is indistinguishable from a typed "N" and reports `OutcomeSuccess`, `Ctrl-C` at the install prompt exited **0** under CPU contention. Give the status one owner on the goroutine that owns the work, recorded by the handler and taken in a defer registered immediately before the recovery defer, so recovery-before-exit is defer order rather than a handshake. **Store the record before cancelling**: cancellation is the only thing that frees a goroutine parked in a select or a subprocess, so every path that can see the cancellation has already seen the record — that ordering, not the atomic, is the correctness argument. Four traps. **A single exit owner still needs to know what the work concluded**: taking 130 unconditionally reported an empty stdout and a failure status for a complete verified install, and the guard must key on the *specific* terminal state, never on "success" — the interrupted-confirmation case this exit owner exists for also returns `OutcomeSuccess`, so an outcome-shaped predicate silently re-breaks the fix. **`os.Exit` in a defer skips every outer defer**, so a caller's scratch-tree cleanup stops running the moment you take the exit rather than returning it. **Pin the child to `GOMAXPROCS=1`** to test a starved-handler race: on the broken tree that fails 9 of 9 every run while the unpinned control fails 0 of 9 across three — the pin is what makes such a test a lock-in, and it is a configuration real single-vCPU runners hit. **And a sub-millisecond window cannot be hit by an externally timed signal**: park the child inside it with I/O back-pressure (fill its narration pipe to one buffer so the next write blocks) and prove the preceding step completed, rather than sleeping and hoping.
- [family: reaped-by-its-own-parent] [REQ-543](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-085/REQ-543-reap-the-commit-hook-with-its-own-parent.md#lessons-learned): **a process is reaped by its own parent and by nobody else**, so terminating a tree leader-first is the one ordering that cannot work. `Cancel` sent SIGTERM to the whole owned group, which killed `git` first; its TERM-deaf `pre-commit` hook was reparented to init, and the later SIGKILL left an unreaped zombie — and **a zombie still satisfies `kill(pid, 0)`**, so the test read the hook as alive. That is also why making the escalation merely synchronous does not fix it: a runner that TERMs the group, waits out grace, SIGKILLs and then polls a predicate treating `Z` as not-alive returns while the raw `kill(pid, 0)` the caller uses still succeeds. Signal descendants bottom-up, level by level from one snapshot, and reach the leader last, so `git` survives long enough to `waitpid()` its own hook: a wait on our own child ends in milliseconds, a wait on init is measured in seconds. Four traps worth carrying. **Level the sweep from a single snapshot, never from "whatever is childless now"** — a backend that respawns a helper in a loop always has a live child, so a re-derived leaf walk never climbs to the parent and hangs forever. **Letting the leader reach its own error path also lets it reach success**, so a hook that happens to exit zero can land the commit the caller is rolling back; that reachability is what earned `ExecuteTransaction` a HEAD-advanced guard it never had. **`ESRCH` from `Getpgid(leader)` does not mean the group is empty** — the leader can be reaped while its descendants run, so routing that into a "cannot prove isolation" branch skips a live group. And the contract has three outcomes, not one: dead where the dying process's parent is a live group member, an **orphan** proved not-running but never reaped, and a **`setsid` escapee** that leaves the group and is never signalled — all three inherent to group ownership without `PR_SET_CHILD_SUBREAPER`, so state them rather than claiming the first.

- 0.286.0 (in place, 2026-09-05): **let the toolchain own build staleness.** The launcher kept its own binary and decided rebuilds by file timestamps, which rebuilt on every checkout that touched a file and would have run stale output after any write that preserved timestamps. Since Go 1.24 `go tool` caches the linked executable by a content hash of every input, so the launcher now declares a `tool` directive, resolves the cached executable with `go tool -C <module> -n do-work-cli`, and execs it from the caller's directory (`go tool -C` without `-n` would run it inside the module, where relative arguments and the default repository root point at the wrong tree). `go run` caches the same way but collapses every exit status to 1 and prints `exit status N`, and callers read the exact status, so it is the wrong verb here. `go tool` rejects `-trimpath`, so worktree copies still compile separately; `GOFLAGS=-trimpath` on the machine is what dedupes the far larger `go test` objects across worktrees.

- [family: fixture-cost-is-subprocess-spawning] [REQ-574](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/REQ-574-bring-do-work-cli-test-files-under-the-30s-budget.md): when a test file overruns the gate's per-file duration budget, measure before rewriting — the cost here was spawning, not asserting. `newFinalizationRepository` ran `git init` plus two `git config` 55 times and `newDeferGateRepository` ran seven git commands 30 times, so `TestMain` builds each baseline repository once and every fixture copies it; `runRetainedInventory` paid two shells and two Go-toolchain probes per case for an executable the build cache already held, so it resolves that executable once and runs it with the argv and environment the shim would have used, leaving exactly one caller on the full shim so the launcher contract keeps a test. Three traps sit on that path: `_dev/tests/run-go-tests-with-budget.sh` sums `Elapsed` only for tests whose name has no `/`, so subtests never count and a parent's number is just its subtests' wall time; `git init --template=` omits `.git/hooks` along with the sample hooks, and a test that writes a real hook then fails on a missing directory; and `t.Setenv` cannot be traded for a per-child `Cmd.Env` when the code under test shells out itself, because the in-process call resolves its own binary from the process PATH. The file that is slow is usually not the file to edit — a package's fixture helper lives in one file and fixing it there speeds up every caller, which is why the declared scope moved from the four slow files to the two that define the fixtures. Whole-module gains read smaller than per-package ones because `go test ./...` runs packages concurrently and hands freed CPU straight to a sibling.

- [family: publication-target-topology-classification] 0.294.2 (in place, 2026-09-05): **a shared version number is a coincidence, not membership.** The undeclared-mirror check discovered mirrors by one test — a tracked VERSION file whose value equals the old version — so an independently versioned component sitting on the same number was reported as a forgotten mirror. In this repository the queue-kanban tool was exempt only by luck (0.236.20 against 0.294.0); in a fresh monorepo where every package starts at 0.1.0 the first root-only release refuses outright, with no manifest field to say "tracked, but not mine". The ownership answer already existed in finalization's recovery discovery and was never shared, so the two readers of "what is a mirror" disagreed while the REQ-569 decision record claimed they agreed. Ownership now lives once in `internal/releaseownership` and is asked BEFORE the value, by both readers, each against the image it judges: HEAD for recovery, the working tree for the planner that is about to rewrite it. Cost of the narrowing, stated plainly: a repository whose only ownership evidence is its root discovers only root mirrors, because nothing else declares membership.
- [family: shipped-module-test-self-containment] 0.294.2 (in place, 2026-09-05): **a test that reads the maintainer tree cannot ship.** Two heavy-lane contract tests walked six levels up to `_dev/tests/heavy-lanes.json`; in an installed copy that walk lands on `<project>/.claude/`, where `/_dev` has never shipped, and `go test ./...` in the installed module failed on the first read. Vendoring fixtures was the wrong repair — what those tests pin is the REAL lane manifest, so a copy would assert nothing — and moving them out of the package was blocked by the unexported identifiers they use. Every maintainer-tree read now sits in one file that `.gitattributes` export-ignores, which keeps the assertions exactly as strong in the maintainer checkout and removes them from consumers entirely. Check the shape by simulating the install (copy `skills/` under a `.claude/` and run the module's tests), not by reading the diff: the walk is the same six `..` either way, and only the landing directory differs.
