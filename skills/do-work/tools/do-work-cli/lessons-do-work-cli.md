# Lessons: do-work-cli

Accumulated lessons for [`prime-do-work-cli.md`](prime-do-work-cli.md). Read this before changing what that prime's **Read first** or **Traps** sections name.

- [family: final-boundary-identity] 0.305.47 (in place, 2026-09-15): **record every completed mutation before validation can fail.** A move deleted an allowed dirty tracked source, then destination recording rejected a replacement before source absence was recorded. Rollback retained an intermediate existing-file snapshot, or no snapshot, and left the source missing. `RecordPublishedMove` binds destination identity before `RecordTouched` records the source state and revalidates created objects. Swapping the old calls alone is insufficient because `RecordTouched` also revalidates and could leave the destination unbound. `TestPublicationRecordingFailureKeepsCreatedTargetsVisibleToRollback` now covers clean, dirty, and rewritten dirty sources with both destination and earlier-object replacement.
- [family: final-boundary-identity] 0.305.47 (in place, 2026-09-15): **repository containment does not preserve directory identity.** The recursive-removal backport closed the enumerated directory and resolved its child paths again. Swapping that directory for a symlink to a repository sibling deleted matching unrelated files. `RemoveAll` now checks the opened directory identity, enumerates through that root, and recurses relative to it. `TestRemoveAllKeepsEnumeratedDirectoryBound` swaps the directory after enumeration and proves the original child is deleted while the sibling survives.
- [family: toolchain-behavior-contract] 0.305.47 (in place, 2026-09-15): **a nested root is not necessarily unresolvable.** On Go 1.26.1, its name resolves correctly, so a test requiring refusal failed despite a valid rename. `TestNestedRootsRefuseUnresolvableNames` now moves the opened directory and replaces its old pathname to establish the actual refusal condition. The CLI build and focused regressions pass on Go 1.24; broader publication fixtures invoke the separate board module, whose Go 1.26 requirement must not be mistaken for the CLI floor. The full CLI suite passes on Go 1.26.1.

- [family: guard-on-one-entry-path] 0.305.31: **a check on the payload is not a check on the cause.** The finalizer validated a release manifest's targets, mirrors and ownership in detail and never asked whether the implementation being released had changed a shipped file, so four versions (0.305.17, .21, .22, .23) were minted for `_dev/tests`-only commits and every check passed. When a rule says "X is a Y", the guard belongs on the condition (does this change ship?) and not only on the artefact Y produces. Found by an audit of the queue-drain run; fixed directly with `RELEASE-WITHOUT-SHIPPED-CHANGE`.
- [family: rule-direction-checked-against-callers] 0.305.30: **a rule unified in one direction is only unified against the callers you read.** REQ-604 made atomic-download's occupancy rule the same for dry-run and live by refusing every existing regular file, and its record stated that `install.md` did not depend on overwriting; `install.md` says four times that a zero-byte SKILL.md from an interrupted download must read as absent so a re-run repairs it, and this command is what that re-run calls, so the repair exited 2 forever. Before choosing the direction of a rule, grep every shipped caller for the behaviour the other direction removes, and pin the caller's contract in a test that runs the caller's own scenario (an empty target, not just an occupied one). Found by an audit of the queue-drain run; fixed directly.
- [family: shipped-module-test-self-containment] 0.305.9: **a skip keyed on a directory a consumer can also have is not a skip.** `TestShippedFastStageManifestSealsTheQueuePathsItsStagesRead` shipped in `fast_stage_evidence_test.go` and skipped when `<six levels up>/_dev/tests` was absent; in an install that path is `<project>/.claude/_dev/tests`, so a consumer with that directory ran the test and failed on a manifest that does not ship. Every test that reads the maintainer tree belongs in the export-ignored `heavy_maintainer_tree_test.go`, where no skip is needed and a missing manifest fails instead of passing silently. Found by an external review of pull request 182; fixed directly.
- [family: projection-before-bounding] 0.303.7: **one unavailable item in an ordered batch is not a verdict on the items behind it.** The queue claim loop `break`ed when a frozen member was no longer selectable, and the frozen ledger keeps queue order — so a request awaiting answers sat between a claimed prerequisite and the sibling that prerequisite had just unblocked, and the sibling was never examined. Worse than a one-pass miss: `continuationArgv` re-emits the identical ledger, so every replay of the returned continuation stopped at the same member and claimed nothing, with no state on disk to say why. `continue` instead, leaving the member unconsumed so a later pass reconsiders it and its exclusion is still reported. Then check what the change makes newly possible: skipping means a blocker can now be recorded *before* the first claim, so the outcome rule that a pass which claimed work reports findings rather than a hard refusal — previously guaranteed by ordering alone — has to be restated after the loop instead of relied on.
- [family: closed-enumeration-for-a-condition] 0.303.7: **an exclusion list is a closed enumeration wearing a condition's clothes.** `isEnclosingFenceCharacter` admitted any block punctuation except `-`, `_`, `*` and `=`, so `#` passed and `### Details` opened a fence that only a later run of three or more `#` could close. A `## Timing` below it is a run of two, never closed it, and `replaceTimingSection` then could not find the section it was replacing — leaving the stale summary and appending a duplicate heading. The four excluded marks were each excluded for a stated reason (a thematic break and a setext underline enclose nothing), and `#` meets that same reason, so it was the enumeration that was incomplete, not the reason. Fix by construct, not by run length: an ATX heading encloses nothing, and neither does a run of seven or more `#`, which CommonMark makes an ordinary paragraph. Sibling to REQ-460 in the same family — that one states the condition, this one shows an exclusion list drifting away from the condition it already had written down beside it.

- [family: time-is-not-authorization] 0.303.5: **cached green evidence is a claim about a tree, and the tree can move while the batch reading it is still running.** Heavy verification hashed the committed tree once, before the first lane, and reused that hash for every later lane's reuse decision — so a lane that edited or committed another lane's fixture left the later lane reusing evidence for inputs that no longer existed. The dirty-tree refusal already existed; it just ran exactly once, at the start. Re-run the cheap identity checks you already own at each decision point and after each step that could invalidate them, rather than adding a cache-invalidation mechanism to track what changed — one `git status` and one `rev-parse` per lane cost less than the state they would replace. Both halves are needed: a lane that *commits* its mutation leaves an apparently clean tree, so dirtiness alone misses it, and `HEAD` alone misses the uncommitted edit.
- [family: lifecycle-section-evidence] 0.303.5: **a reader that strips presentation constructs has answered "is this a picture of a record", not "can a reader see this at all".** `activeEvidenceLines` correctly stopped at fences and headings, so a marker quoted inside a code block could not authorize completion — and it treated HTML comment bytes as ordinary visible text, so a Blocked resolution entry wrapped in `<!-- ... -->` completed the REQ while showing the human nothing. Hidden text is a separate class from quoted text and needs its own answer. Refusing the whole payload on `<!--` is the right size: a comment cannot establish visible evidence, an unclosed comment has no end to scan to, and a writer who wants a comment beside a genuine marker moves it out of the evidence payload. Do not reach for a structured-disposition schema when the defect is that one construct was never classified.
- [family: cross-action-exception-closure] 0.303.5: **a phase gate written for the successful path leaves the failure path with no route to the same authority.** `advance` ran finalization only when the projected phase was already `finalize`, so a REQ that failed in planning, implementation or before its tests kept its checkpoint claim with no way to archive — the canonical finalizer was reachable only by the requests that did not need rescuing. Admit the early transition through the *same* decode that already binds identity: `prepareBoundJournal` took one `requiredTransition` comparison beside its existing request-id comparison, so the new route cannot skip a check the old route made. A second finalizer for failures would have been the same code with a different set of things to forget.
- 0.303.5: **dispatching on the first token of an argv breaks any command whose identity is the whole argv.** A frozen queue continuation leads with a REQ id, so once its first member was claimed and moved to working, `advance` read that id, found the request outside the queue, and ran the single-request path — the remaining frozen members were silently never claimed. Ask the parser that owns the shape whether these arguments *are* that shape, before dispatching on where one of their tokens happens to point. Reusing that parser also kept a gate option value or a child argv leading with a REQ id from selecting the path, because it already refused a continuation carrying no frozen members.
- [family: commit-preflight-before-side-effect] 0.303.5: **validation that lives in the write path runs after the side effect.** `RunTimedCommand` checked run identity, request identity, category, operation and outcome inside `appendMeasuredEvent`, the single write path — correct for the recorded-event caller, useless for the measured-command caller, which had already executed the child by then. An invalid `--category` ran the gate, let its writes land, and then reported a usage error. Split caller-input validation into a function that does no I/O and call it from both, before `exec`. Two consequences worth pinning: a rejection before launch and a failure after it are different outcomes needing different codes, and the post-execution failure must carry the child's own exit status — including zero — because the child did run and its result is the fact the caller came for. Exit 127 means the command never launched; it is not the usage-error contract.

- [family: background-worker-self-bound] 2026-09-05 (in place): **background work must stop itself if its parent dies.** During the review of REQ-581 (making descendant-cleanup tests detect a real process-group leak), six unbounded shell loops were added for a synthetic-load check. The parent died before its trailing `kill`; the incident report records roughly 4.5 hours of orphaned load and 24 CPU-hours consumed. An `EXIT` trap still cannot handle SIGKILL. Start from the bounded Bash/zsh pattern in [Testing → Background Work and Synthetic Load](../../crew-members/testing.md#background-work-and-synthetic-load), with a deadline inside each worker; cleanup signals only end it earlier. Use the smallest justified load experiment and label its measurement window as loaded. Cleanup-test fixture bounds must outlast their failure assertions so natural expiry cannot hide a leak.

- [family: closed-enumeration-for-a-condition] [REQ-460](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-081/REQ-460-make-outside-text-delimiter-containment-condition-complete.md#lessons-learned): when a contract states a condition, testing membership in a list of examples is a different contract that happens to agree on the examples — `summaryRequiresContainment` recognized ten prefixes and inlined `***`, `___`, `+++`, `:::note`, `$$`, `===`, bare `-`/`*`/`+`, bare `1.`, pipe tables and indented code. **A partially-correct enumeration is worse than an empty one**: `---` and `* * *` were caught while `***` and `___` were not, so the class looked handled. Two traps worth carrying: a trim that runs *before* the test can destroy the very bytes that constitute the structure (`TrimLeft(" \t")` made indented code unreachable), and a widening like this is only provable as safe by differential — 160,906 inputs, old predicate against new, 0 weakenings, which no fixture set establishes. Finally, know where the value is written before reasoning about its hazard: this summary lands mid-line at two sites, so it can never start a line, and the delimiter hazard the widening was justified by is unreachable there — the review caught that, and the decision now stands on defence-in-depth for a future line-start writer instead.
- [family: writer-anchored-marker-position] [REQ-528](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-081/REQ-528-anchor-resolved-question-marker-matching-to-its-position.md#lessons-learned): a marker the writer composes onto a shared line must be read at the position the writer places it, never by containment over the line — but **position anchoring alone is not sufficient when the neighbouring field is human text that can occupy the same position**. `allResolvedQuestionsMatch` searched the whole `- [x]` line, so an answer summary supplied the disposition and cancelled an answered REQ; anchoring to the writer's separator closed that, and a summary *beginning* `Discarded: ` still forged it, because the label and the summary share one position and the document records nowhere which wrote those bytes. The contract needs both halves: refuse the collision on the write side, and read only at the anchored position. Sibling to `closed-enumeration-for-a-condition` (REQ-460) — that one stated the condition, this one states where it is evaluated and who is allowed to have written the bytes. Three more traps: a line where the anchor is not unique has no determinable marker and must fail toward the non-terminal verdict (measure the cost first — 2 of 124 real lines carry a second arrow, from this repo's own `A → B` style); a guard that fires for every outcome rather than only the ambiguous one is defense nothing earned, so pin the carve-out or a later hardening will pass silently; and attack the built command, not the test harness — the first implementation's lock-ins were real and all green while the forgery still worked end to end.
- [family: closed-enumeration-for-a-condition] [REQ-461](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-081/REQ-461-require-affirmative-project-owned-release-targets.md#lessons-learned): the family's second sighting in three REQs, so its trap is now promoted into the prime. `installedReleasePath` denylisted `vendor`, `node_modules`, `.claude/skills` and `generated`, so `third_party/do-work`, `dist/skills/do-work` and any differently-named cache tree were accepted for a consumer release. The replacement proves ownership from two declarations the repository already makes — Git's index, and no `SKILL.md` between the root and the target's parent — and **neither half is sufficient alone**: a committed vendored package satisfies the index and is caught only by its marker, while a `dist` or cache tree carries no marker and is caught only by the index refusing to claim it. Four traps worth carrying. **Anchor an attestation on the directory the file actually lands in**: walking up to the nearest *existing* ancestor reaches a repository root that always attests, so every not-yet-created tree was accepted — the realistic case — while only the already-existing one refused. **A negative test can pass by fixture accident**: deleting one `placeholder` line flipped this REQ's sole create-path test from refusing to accepting, and the neuter table showed the same hole from the other side by *not* reddening it. **`git ls-files -- <dir>` prints `<dir>` itself** for a gitlink or tracked symlink, so a directory with no tracked file inside it attests; filter to entries strictly within, and use `-z` so git's path quoting cannot break the prefix test. **Pair every refusal gap with its own remedy in a typed result**, because one shared remedy line was wrong for two of three gaps and steered a consumer whose file was merely uncommitted toward the maintainer escape hatch. Finally: when a fix renames a refusal code, a single revert differential cannot isolate the condition — rows redden on the rename. Run one differential per half.
- [family: single-exit-owner] [REQ-525](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-085/REQ-525-block-the-install-confirmation-before-signalling-it.md#lessons-learned): **two goroutines that can both reach `os.Exit` have no correct ordering** — whichever gets there first decides the status. A signal handler doing `os.Exit(130)` raced the ordinary return path, and because a cancelled confirmation is indistinguishable from a typed "N" and reports `OutcomeSuccess`, `Ctrl-C` at the install prompt exited **0** under CPU contention. Give the status one owner on the goroutine that owns the work, recorded by the handler and taken in a defer registered immediately before the recovery defer, so recovery-before-exit is defer order rather than a handshake. **Store the record before cancelling**: cancellation is the only thing that frees a goroutine parked in a select or a subprocess, so every path that can see the cancellation has already seen the record — that ordering, not the atomic, is the correctness argument. Four traps. **A single exit owner still needs to know what the work concluded**: taking 130 unconditionally reported an empty stdout and a failure status for a complete verified install, and the guard must key on the *specific* terminal state, never on "success" — the interrupted-confirmation case this exit owner exists for also returns `OutcomeSuccess`, so an outcome-shaped predicate silently re-breaks the fix. **`os.Exit` in a defer skips every outer defer**, so a caller's scratch-tree cleanup stops running the moment you take the exit rather than returning it. **Pin the child to `GOMAXPROCS=1`** to test a starved-handler race: on the broken tree that fails 9 of 9 every run while the unpinned control fails 0 of 9 across three — the pin is what makes such a test a lock-in, and it is a configuration real single-vCPU runners hit. **And a sub-millisecond window cannot be hit by an externally timed signal**: park the child inside it with I/O back-pressure (fill its narration pipe to one buffer so the next write blocks) and prove the preceding step completed, rather than sleeping and hoping.
- [family: reaped-by-its-own-parent] [REQ-543](https://github.com/knews2019/skill-do-work/blob/main/do-work/archive/UR-085/REQ-543-reap-the-commit-hook-with-its-own-parent.md#lessons-learned): **a process is reaped by its own parent and by nobody else**, so terminating a tree leader-first is the one ordering that cannot work. `Cancel` sent SIGTERM to the whole owned group, which killed `git` first; its TERM-deaf `pre-commit` hook was reparented to init, and the later SIGKILL left an unreaped zombie — and **a zombie still satisfies `kill(pid, 0)`**, so the test read the hook as alive. That is also why making the escalation merely synchronous does not fix it: a runner that TERMs the group, waits out grace, SIGKILLs and then polls a predicate treating `Z` as not-alive returns while the raw `kill(pid, 0)` the caller uses still succeeds. ## Advance phase table

Queue-mode `advance` (no target, target tokens, or queue flags) selects from canonical `next` evidence, records archive-collision and dependency-cycle holds, runs blocked probes, and commits unblock/claim transactions per request. Its typed `queue_advance` evidence freezes targeted membership and returns stateless continuation argv. Exact working/archive targets remain byte-for-byte read-only until a supported mechanical phase receives its exact request-bound inputs; that invocation runs the gate and returns ordered `gate_records`. A missing action-owned input returns `needs_input` with exact argv, while judgment phases return no command and are named `agent judgment: <what>`. Explicit `advance --checkpoint` may change only `do-work/CHECKPOINT.md` and preserves every structurally discovered live claim record.

| Evidence boundary | Route A | Route B | Route C |
|---|---|---|---|
| Queue | queue-mode `advance` selects and commits the claim; successful blocked probes commit unblock then claim | same | same |
| Claimed, before build | triage → advance executes `estimate-p50` → planning-skip judgment | triage → advance executes estimate → planning-skip → exploration → scope → `preflight` plus green-evidence check | triage → advance executes estimate → planning → exploration → scope → `preflight` plus green-evidence check |
| Built | advance executes `qualify` → focused-test/green-gate evidence → testing judgment | advance executes `qualify` + `scope-drift` → focused-test/green-gate evidence → testing judgment | same |
| Tested | review → lessons/orientation → heavy hold when lanes were selected → `finalize` through advance | same | same |
| Archive | missing terminal provenance → `recover-finalization --discover`; otherwise complete | same | same |

Exact `##` sections are intermediate evidence. A clean preflight has no durable section, so the preflight phase remains current until `## Implementation Summary` exists. After orientation, advance requires one action-authored manifest, binds its ID/path during the finalizer's single decode, and returns the finalizer's ordered evidence unchanged. `ADVANCE-EVIDENCE-MISSING` refuses contradictory ordering or unusable identity; `ADVANCE-PHASE-UNKNOWN` refuses impossible tree/status/route combinations. Every gate or finalization record binds the exact discovered request ID and path. Queue-mode `advance` and the focused-test gate consume `nextselection`'s bounded blocked-probe evidence; `run-blocked-check` is not a second authority.

## Scoped command contracts

- Preserve unknown frontmatter and body bytes unless a command explicitly owns the field being changed.
- Discover once per decision boundary. Queue composition must rediscover after every committed mutation before planning the next request; downstream logic within one boundary consumes typed records and exact paths instead of rescanning.
- Reservation markers under `do-work/.req-reservations/` are durable coordination metadata and must be observed despite hidden-directory pruning.
- Cleanup operation groups preflight independently; a dirty group is reported without blocking unrelated safe groups.
- Entirely untracked `Status: consumed` run scratch is the sole non-rollback deletion; revalidate its exact inventory immediately before removal.
- Doctor diagnosis is byte-for-byte read-only. Only `--repair-timestamps` mutates, and blank recovery remains exact cleanup consent.
- Standalone `next` selection is byte-for-byte read-only. It executes a scoped `blocked_check` only through the in-process owned process-group runner; every record retains exact request-path and raw probe/unblock evidence.
