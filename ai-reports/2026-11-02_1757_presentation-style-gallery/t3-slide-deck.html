The 16 MB limit that never ran

Release 0.306.5 (2026-10-19) fixed it. Since then, the launcher stops a backend's output at 16 MB and reports it. Before, the limit code existed, but it never ran.

Cause

The limit lives in Write

The launcher keeps each backend's output in a buffer. The buffer has its own Write method. Write is the only place that checks the 16 MB limit.

remaining := 16*1024*1024 - buffer.captured.Len()
if len(data) > remaining {
	data = data[:remaining]
	buffer.truncated = true
}

report_second_opinion.go:1075-1079

Cause

The old buffer embedded bytes.Buffer

Embedding gives the struct every method of bytes.Buffer for free. One of those promoted methods is ReadFrom.

type secondOpinionBuffer struct {
	bytes.Buffer
	truncated bool
}

aa61c81a (old struct)

Problem

io.Copy picks ReadFrom

Go's os/exec moves the backend's output through a pipe with io.Copy. io.Copy asks: does the buffer have ReadFrom? The old buffer said yes. So io.Copy called ReadFrom and never called Write.

aa61c81a commit messagereport_second_opinion.go:1141

Problem

What it cost

16,777,300

bytes kept by the old buffer shape, with truncated=false

There was no limit. A backend that prints too much keeps growing in memory. The error "backend output exceeded capture limit" could never fire, because the truncated flag was never set.

old (embedded):  io.ReaderFrom=true  captured=16777300 bytes  truncated=false

reproduction run, 2026-11-02report_second_opinion.go:1194-1195

The reproduction is a short Go program written for this gallery that copies the old and new buffer shapes. It is not project code.

Change

The fix: a named field

A named field keeps its methods on the field. The buffer type has no ReadFrom now, so io.Copy must call Write.

 type secondOpinionBuffer struct {
-	bytes.Buffer
-	truncated bool
+	captured     bytes.Buffer
+	truncated    bool
+	mirrorPrefix string
+	pending      []byte
 }

Proof

Proof, and what changes for you

If a backend prints more than 16 MB, the second-opinion run keeps the first 16 MB and reports "backend output exceeded capture limit". A test pins this. It sends 16,777,300 bytes and expects exactly 16,777,216 bytes plus an error.
