The story every page tells

Release 0.306.5 (2026-10-19), from REQ-702 (the second-opinion launcher shows progress while a backend runs). The same change fixed a hidden bug: the 16 MB output limit had never worked.

  1. The limit lived in WriteThe launcher's buffer has its own Write method that stops at 16 MB.
    report_second_opinion.go:1075
  2. The buffer embedded bytes.BufferSo it also got bytes.Buffer's ReadFrom method for free.
    aa61c81a (old struct)
  3. io.Copy chose ReadFromGo's copy prefers ReadFrom. Write never ran, so the limit and its error never ran.
  4. Fix: a named fieldThe buffer is now a field called captured. No ReadFrom, so every byte goes through Write.
    report_second_opinion.go:1055
  5. The limit worksOutput stops at 16,777,216 bytes and the run reports "backend output exceeded capture limit".
  6. A test pins itIt sends 16,777,300 bytes and expects exactly 16 MiB plus the error. It passes today.
    report_second_opinion_test.go:804

The eight pages

T1

Cause-and-effect chain

What
One card per link: because, so, therefore. Pipes join them.
Best for
Bugs, incidents, any "why did this happen".
Watch for
Small changes give short, thin chains.
 T2

Stepped diagram

What
A diagram beside numbered steps. Each step lights one part.
Best for
Data flow, architecture, "how it works".
Watch for
The diagram must be true to the code.
 T3

Slide deck

What
One idea per screen. Arrow keys or space move on.
Best for
Showing the report on a call.
Watch for
Long reports become many clicks.
 T4

Annotated terminal replay

What
Real command output with numbered notes on the lines that matter.
Best for
CLI and backend work, where screenshots do not exist.
Watch for
Needs real output, never invented.
 T5

Hover glossary

What
Plain prose. Every technical word explains itself on hover or tap.
Best for
Readers new to the code or the project words.
Watch for
Too many underlined words become noise.
 T6

Three depths

What
One sentence, then one screen, then the full details folded away.
Best for
Busy readers who may stop early.
Watch for
Hidden details are easy to miss.
 T7

Comic strip

What
Six panels. The parts of the code are characters who talk.
Best for
Incident stories and onboarding. The most fun.
Watch for
Turns into decoration fast. Facts must stay exact.
 T8

The combination (my pick)

What
One-line verdict, cause chain, stepped diagram, terminal proof, glossary, details folded. Press D for deck mode.
Best for
The new default for every ai-report.
Watch for
Longest page of the eight.

How to compare them

The 30-second test

After 30 seconds on the page, can you say why the limit never ran, in one sentence?

The proof test

Pick any claim. Can you find the file, commit or test that backs it?

The phone and no-motion test

Does the page still read well on a narrow window and with reduced motion turned on in your system settings?
