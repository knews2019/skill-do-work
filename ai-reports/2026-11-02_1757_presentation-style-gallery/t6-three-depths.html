What changed for you

If a backend (codex, gemini or agy) prints more than 16 MB, the launcher now cuts it and reports "backend output exceeded capture limit". Before, it kept every byte in memory with no error. Runs that stay under 16 MB behave as before.

Why io.Copy skips Write

The launcher sets the two buffers as the command's stdout and stderr. They are not files, so os/exec makes a pipe and copies it with io.Copy.

io.Copy checks whether the writer has a ReadFrom method. If it does, io.Copy calls ReadFrom and never calls Write.

The old buffer used embedding, so ReadFrom was a promoted method on it. bytes.Buffer.ReadFrom knows nothing about our 16 MB cap. The fixed buffer keeps bytes.Buffer in a named field, so ReadFrom stays on the field and the buffer has only Write.

The code now explains this itself, above the struct:

// captured is a named field, never embedded: an embedded bytes.Buffer promotes ReadFrom, io.Copy prefers it, and
// neither the cap nor the mirror in Write would ever run.

The test that pins it

head -c 16777300 /dev/zero prints 84 bytes more than 16 MiB. The test fails if the launcher keeps any other number of bytes than 16,777,216, or if no error comes back. This is the pin for this bug.

func TestSecondOpinionCaptureCapsBackendOutput(t *testing.T) {
	previousSink := secondOpinionProgressSink
	secondOpinionProgressSink = io.Discard
	t.Cleanup(func() { secondOpinionProgressSink = previousSink })
	captured := secondOpinionCapture(context.Background(), secondOpinionProgress{}, t.TempDir(), "/usr/bin/head", "-c", "16777300", "/dev/zero")
	if len(captured.stdout) != 16*1024*1024 || captured.err == nil {
		t.Fatalf("captured %d bytes, err=%v", len(captured.stdout), captured.err)
	}
}
