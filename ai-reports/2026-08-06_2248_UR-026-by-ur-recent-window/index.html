Before

Active became impossible after shipping

The predicate only accepted a user request with a non-terminal requirement. Once every requirement completed, every user request failed the filter and the By UR lens went blank.

The window chips stayed visible but rerendered only Columns, so changing 24 hours, 48 hours, or 7 days had no visible effect in By UR.
After

Active includes open or recent work

The predicate now accepts a user request when any member is open or appears in the shared recently-done set. A qualifying user request still shows all of its requirement cards, because the user request is the unit of this lens.

Changing the window rerenders whichever lens is visible, invalidates the other cache, and updates the empty-state and hidden-count copy with the selected span.

Lessons

What keeps this from regressing

The important lesson is structural: a render cache makes every input-changing control a call site, even when the handler appears unrelated to that lens.

Predicate design

“Active” was partly a clock question

A status-only name hid the fact that readers also expect recently completed work. Two views disagreeing over one dataset was the strongest clue.

Test altitude

Assert inside the handler

The renderer names occur throughout the bundle. Slicing the window handler and asserting inside that block is what made the broken version fail first.

Cache discipline

Audit sibling controls

Whenever a cache guards rendering, every control that changes its inputs must either refresh that view or invalidate it for the next switch.
