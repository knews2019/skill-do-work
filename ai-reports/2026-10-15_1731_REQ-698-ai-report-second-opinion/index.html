1. How a Run Flows: Trigger → Backend → Staging File → Guards → Judge → Banner

Pipeline implemented in skills/do-work/tools/do-work-cli/internal/toolboxcommands/report_second_opinion.go. Hand-authored SVG architecture diagram

Problem & Architectural Shift

AI-generated technical reports can become dense or drift from repository code. Asking a second model to rewrite a report ad hoc risked overwriting index.html, inventing model names, leaving stray files outside the bundle, or shipping broken layouts.

REQ-698 moves all mechanical enforcement into the Go subcommand ai-report-second-opinion while keeping editorial rules in the shipped prompt template ai-report-second-opinion-prompt.md.

Key Guardrails in the Flow

Two-stage native model verification: A 90-second read-only probe resolves the exact model slug before the prompt is filled (so the <cli>-<model>- asset prefix is real), and the generation output's native envelope must report the identical model.

Process-group supervisor (F1 remediation 2abd7939): A POSIX shell supervisor stays alive as the process-group leader until ownedprocess.TerminateGroup stops all descendants, preventing background child processes from writing after capture returns.

Lessons Learned

  • Native identity over requested flags (native-backend-identity): CLI flags and exit code 0 do not prove which model ran; Codex needed stderr startup-header parsing while Claude, Gemini, and AGY exposed structured JSON usage/init fields.
  • Separate backend exit from group lifetime (reaped-by-its-own-parent): Calling Cmd.Wait on the backend leader before group teardown erased PGID ownership proof and let a redirected child write 300ms after return; keeping a lightweight POSIX supervisor alive until TerminateGroup finishes closed the race.

Open Questions & Recorded Limitations
