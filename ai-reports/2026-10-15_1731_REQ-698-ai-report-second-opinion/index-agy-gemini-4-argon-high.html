TL;DR (3 sentences): ai-report second-opinion is a built-in command in the do-work-toolbox skill and Go CLI (do-work-cli) that asks a second AI model to rewrite an existing HTML technical report so it is clearer and fact-checked against the codebase. To protect the original report, the Go launcher forces the model to write into a hidden temporary staging file, checks that no existing report files or outside Git paths changed, and tests the new layout in a headless browser at desktop and phone sizes. Only after every safety and rendering check passes does the launcher publish the sibling report (index-<cli>-<model>.html), save the model's review notes (<cli>-<model>-reply.md), and add a small link banner at the top of the original index.html.

1. The Big Picture: Six-Stage Guarded Pipeline

Before REQ-698 (captured under UR-156), asking a second model to improve a report risked overwriting index.html, inventing model names, or breaking mobile layouts. The new pipeline puts editorial judgment in a Markdown prompt template while locking all file safety, model identity verification, and browser testing inside the compiled Go binary.

3. How It Works: Modes, Adapters & Step-by-Step Walkthrough

Users can invoke a second opinion in four ways depending on whether they are inside an active AI coding session, targeting a specific model, running a multi-model batch, or typing in a plain terminal. Select a mode tab below to see how the dispatcher and Go CLI handle it.

1. Session Mode — Uses the Calling Agent's Own CLI & Active Model

When a user says "generate a second opinion" or runs ai-report second-opinion [<bundle-dir>|latest] inside an active AI session, ai-report.md instructs the calling agent to pass its own CLI and known active model slug explicitly. If the agent cannot determine its exact active model slug, it must stop and explain why—a CLI's configured default is never trusted as proof of the active chat's model. 

skills/do-work/tools/do-work-cli.sh --repo-root . --format json ai-report-second-opinion --backend <own-cli> --model <own-slug> [bundle|latest]

2. Targeted Mode — Runs Exactly One Named Backend (Never Substitutes)

When a user names a specific backend (such as "Codex, generate a second opinion" or --backend codex [--model <slug>]), the CLI runs only that backend (`codex`, `gemini`, `agy`, or `claude`). If the binary is not installed or the native probe resolves to a different model than requested, the run fails closed and never substitutes another backend or model. 

skills/do-work/tools/do-work-cli.sh --repo-root . --format json ai-report-second-opinion --backend codex [--model <slug>] [bundle|latest]

3. Batch Mode (--all --exclude <own-cli>) — Sequential Multi-Model Sweep

When a user asks to "generate second opinions from all models", the calling agent passes --all --exclude <own-cli>. The CLI visits codex, gemini, and agy sequentially (note: claude is supported in targeted/session mode but is not part of the --all batch list), taking a fresh bundle snapshot before each backend so earlier passing banners are preserved while recording any skipped or failed backend in the final summary. 

skills/do-work/tools/do-work-cli.sh --repo-root . --format json ai-report-second-opinion --all --exclude <own-cli> [bundle|latest]

4. Plain Terminal Fallback — First Installed Engine Once (No Retry)

When invoked directly from a plain shell without an active agent session (omitting both --backend and --all), report_second_opinion.go:57-69 sets InvocationMode: "terminal" and checks PATH for the first installed binary in the order codex → gemini → agy. It runs only that first installed backend once and never falls back to the next binary if the run fails. 

skills/do-work/tools/do-work-cli.sh --repo-root . --format json ai-report-second-opinion [bundle|latest]

Step-by-Step Execution Flow

STEP 1 · PREFLIGHT

Resolve Bundle & Snapshot

Walks ai-reports/ in memory (following superseded_by links), verifies no symlinks exist, checks that git status has zero outside paths, and snapshots every file's bytes, mode, and inode.

STEP 2 · NATIVE PROBE

Verify Model Identity

Runs a 90s read-only probe before building the prompt so the asset prefix <cli>-<actual-model>- is verified from native CLI metadata rather than guessed from flags.

STEP 3 · STAGED RUN

Supervised Generation

Creates a hidden .<prefix>staging-*.html file, fills the prompt template, and runs the backend inside a POSIX process-group supervisor with a 16-minute timeout and 16 MiB output cap.

STEP 4 · GUARD & PUBLISH

Check Invariants & Save

Verifies zero outside Git dirt, byte-identical pre-existing bundle files, matching generation model slug, and a valid opening backlink, then atomically publishes the sibling HTML and -reply.md.

STEP 5 · RENDER JUDGE

4-Pass Headless Browser QA

Copies the bundle to a temp folder with the candidate page as index.html and runs headless Chromium at 1440×1000 and 390×844 in light and dark themes, checking for overflow or broken links.

STEP 6 · BANNER LINK

Idempotent Original Link

Only if judgeRender returns pass and index.html is still byte-identical to the pre-run snapshot, inserts a marker-wrapped <aside> banner right after <body>.

Deep Dive: How the Process-Group Supervisor Fixed Review Finding F1 (2abd7939)

During the first independent review, a reviewer test probe spawned a background child process that redirected stdout/stderr, slept 300ms after the main backend process exited, and wrote a file. Because the original runner called command.Wait() on the backend leader before running ownedprocess.TerminateGroup, the operating system had already reaped the leader's process ID, causing Getpgid to return ESRCH and leaving the background child alive to write after capture returned.

Commit 2abd7939 fixed this by wrapping the backend inside a tiny POSIX shell supervisor (secondOpinionSupervisor in report_second_opinion.go:570-578). The supervisor starts the backend in the background with closed stdin and closed file descriptor 3, waits for the backend to exit, writes the backend's numeric exit status to file descriptor 3, and then blocks reading from parent-held stdin until ownedprocess.TerminateGroup finishes terminating every descendant bottom-up.

4. Decisions & Trade-offs: UR-061 Request vs. REQ-698 Implementation

This work began in consumer repository iwr2-imprint-wright as UR-061 / REQ-287 before being migrated upstream into skill-do-work2 as UR-156 / REQ-698. All core behaviors shipped as requested, with 7 architectural adjustments made to fit upstream suite invariants:

Design Area Asked in Consumer UR-061 (REQ-287) Built Upstream in REQ-698 (UR-156) Why This Trade-off Was Made
1. Package ownership Standalone project skill .claude/skills/ai-report-second-opinion/ linked from make-ai-report-with-screenshot. Built-in form in skills/do-work-toolbox/actions/ai-report.md + prompt in skills/do-work-toolbox/docs/. Migrating upstream distributes the feature to every consumer project automatically via just run-do-work-update.
2. Execution engine Bash script scripts/run_second_opinion.sh shelling out to CLIs and ai-report-judge. Compiled Go subcommand ai-report-second-opinion in report_second_opinion.go calling judgeRender in-process. Follows the suite's "programs beat prose for anything mechanical" rule and reuses the Go catalog walker, atomic file publisher, and PGID teardown.
3. Staging & reply collisions Prompt gave the model the final index-<cli>-<slug>.html filename directly; reply collision behavior was unspecified. Model writes to hidden .<prefix>staging-*.html; launcher publishes paired index-<cli>-<slug>[-N].html and <cli>-<slug>[-N]-reply.md and rewrites staging paths in the reply (D-06, D-08). Prevents aborted runs from leaving half-written final pages and guarantees repeat runs never overwrite earlier -reply.md files.
4. Model resolution Read model slug after the run (assuming a codex exec --json header). Runs a 90s read-only native probe first so the asset prefix is verified before prompt generation, then verifies the generation envelope matches; parses Codex's stderr startup header (D-05). Installed codex exec --json does not emit model identity; probing first ensures the model gets a real <cli>-<model>- asset prefix.
5. Mutual-link placement Update 1 asked to pick either a banner inside index.html OR a link on the catalog page ai-reports/index.html. Inserts a marker-wrapped <aside> banner after <body> in index.html and resolves latest in memory without writing ai-reports/catalog.json (D-02). Modifying ai-reports/index.html or catalog.json would dirty paths outside the target bundle and trip the strict outside-bundle Git guard.
6. Rerun idempotency Asked both for numeric collision suffixes on existing files and for a second run to report banners as "already present" with no change. Banner insertion is idempotent per filename (secondOpinionBanner), while a fresh CLI run allocates -2 and adds a banner for the new file (D-01). Reconciles both requirements without silently skipping a requested generation or overwriting the first second-opinion page.
7. Live test target Test on consumer bundle 2026-10-11_0935_imprintwright-onboarding/ from a Claude Code session plus full batch. Tested on upstream 2026-10-09_1916_REQ-632-activity-correlation-determinism/ with targeted Codex, pinned Claude, batch, and an authorized AGY retry. The builder ran inside an upstream Codex session where live Claude session identity was unavailable, so Claude was tested via explicit --backend claude --model claude-opus-5-5.
Inspect all 11 Recorded Engineering Decisions (D-01 through D-12 in REQ-698)
  • D-01 (Per-filename banner idempotency): Re-running banner insertion for the same filename is a no-op (already-present), whereas a fresh generation run allocates a numeric suffix (-2) and adds a new banner for that new file.
  • D-02 (In-memory catalog resolution): Resolves latest and supersession chains via reportIndexWalk in memory so catalog files outside the bundle are never dirtied.
  • D-03 & D-04 (Typed JSON result & launcher prompt env): Added AIReportSecondOpinionResult to result_model.go and exported DO_WORK_AI_REPORT_SECOND_OPINION_PROMPT from do-work-cli.sh so cached binaries locate the prompt in both source and installed layouts.
  • D-05 (Two-stage native model verification): Uses a 90s read-only native probe before generation and requires identical native model metadata on the generation run.
  • D-06 & D-07 (Disposable staging leaf & strict preservation): Models write to a hidden .<prefix>staging-*.html leaf; pre-existing files are checked by inode, mode, and byte content; symlinks and outside-bundle Git changes (including rename sources) fail closed without auto-reverting.
  • D-08 (Portable reply & source-map links): Rewrites staging file paths to the published relative page filename inside -reply.md, and requires plain-text repository paths when remote commit reachability is unverified.
  • D-09 (Semantic opening backlink parser): Fixed secondOpinionBacklink in commit 2f5cd87a to allow reordered attributes, single/unquoted href values, and harmless inline tags (<strong>, <code>, <span>) while still requiring the backlink to open <body>.
  • D-10 (Literal write-set expansion): Listed the four concrete REQ-632 live proof files in REQ-698 frontmatter write_set to satisfy the literal scope comparator.
  • D-11 & D-12 (POSIX process-group supervisor & lesson promotion): Added secondOpinionSupervisor in commit 2abd7939 to hold PGID ownership until TerminateGroup finishes, and recorded native-backend-identity and reaped-by-its-own-parent in lessons-do-work-cli.md.

7. Glossary of Terms & Acronyms

Plain-language definitions of every acronym and suite-specific term used in the report:

AGY (Antigravity CLI)
The command-line interface (agy) for Google Antigravity, invoked headlessly with --output-format stream-json -p.
CLI (Command-Line Interface)
A text-based executable run from a shell, such as do-work-cli, codex, gemini, agy, or claude.
ESRCH (No Such Process)
The Unix kernel error returned when a process or process group ID no longer exists because its leader was already reaped.
Inode
The filesystem's internal numeric identifier for a file object. Checking os.SameFile ensures a file was not deleted and recreated.
judgeRender (ai-report-judge)
The Go function in report_judge.go that serves a report bundle over local HTTP and checks desktop/phone light/dark renders in headless Chrome.
Marker-Wrapped Banner
An <aside> link block wrapped in <!-- second-opinion-banner:index-... --> comments, inserted right after <body> in index.html.
Native Identity Probe
The 90-second pre-generation check that extracts the actual model slug from the backend CLI's own metadata rather than trusting user flags.
P-A-U Loop (Plan-Apply-Unify)
The do-work execution lifecycle where a builder plans the change, applies it within a declared write set, and unifies verification evidence.
PGID (Process Group ID)
A Unix identifier shared by a parent process and its child processes so the launcher can terminate the entire tree when a run finishes.
REQ / UR (Request / User Request)
A tracked engineering task (REQ-698) extracted from a verbatim user prompt capture (UR-156) in the do-work queue.
Staging Leaf
The hidden temporary file (.<cli>-<model>-staging-*.html) created in the bundle for the model to fill, deleted automatically when the run exits.
workspace-write
Codex CLI's OS-level sandbox flag (-s workspace-write) that restricts file modifications to the current working directory (the report bundle).
