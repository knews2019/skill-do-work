Depth 2 of 3: the recommendation

Recommendation: O2 as a pilot, with a stop rule

Run O2 by hand on the next two lineages you would review anyway. Use a pinned source checkout of Tinka at 77ba29c and keep its files outside the repository. Ship no docs and no code during the pilot: the recipe is under "Check it yourself" below.

Why not build now. The canvas gives two things that do-work lacks: one view of a whole lineage, and a note that stays attached to a page. The live check also showed that a capture cannot replace the page (K1) and that the canvas cannot leave this computer (K2). Whether the two gains outweigh those two limits depends on how you review, and only use can show it.

Why not adopt nothing now. The recipe costs nothing in the repository, and the first run is already done.

The council's order: agree, with three changes

The council chose O2 as a pilot, O3 only if the pilot passes, O4 deferred. The evidence supports that order. O4 has to wait because an HTML tile can write to the canvas today, and O3 has to wait because K1 and K2 are open. Three points differ.

  1. The pilot ships nothing. The council's O2 starts with a docs section. A shipped section recommends a 30-day-old tool to every do-work user before one real review has used it. Write the section when the pilot passes.
  2. "The pilot passes" needs a test. The council gave none. The pilot rule on the right is that test.
  3. The scores are not evidence. The 72, 66, 61 and 55 are the council's own grades. No source can check them, so this report does not use them.
Pilot rule

The result that means "adopt nothing"

The pilot covers two lineages, or 14 days if two do not come up. Write feedback on the canvas first. Then count.

Adopt nothing (O1) when any one of these is true:

  1. R1. Fewer than half of your feedback points were written on the canvas before chat.
  2. R2. No feedback point used something chat cannot do: a pin on a place in a capture, a comment on a quoted phrase of a reply, or a note you read again in a later session.
  3. R3. Tinka changed git status --porcelain or AGENTS.md in the repository.

Go to O3 only when R1 and R2 pass on both lineages and R3 never happens. Slow hand work is not a reason to stop: it is the reason for O3.

Limits: what was not checked, and why
  • L1. board overview --out failed with read ECONNRESET. The container runs as root and Tinka starts Chromium without --no-sandbox (lib/overview.mjs:99-100). The canvas picture was taken with Playwright from the ?overview view instead. On a normal user account this was not tried.

  • L3. A live HTML tile from a second origin (O4) was not shown to work: the full view created no frame for the URL item with openMode: preview. Other open modes were not tried.
  • L4. The installed path (tinka-install.mjs) was not run, so the daily update check and the GITHUB_TOKEN header are read from code only.
  • L5. No outbound network trace was taken. "A source checkout never checks for updates" rests on lib/cli.mjs:148-150 and the missing INSTALLATION.json.
  • L6. Tinka's own tests were not run, and its code was not audited beyond the files the seeds cite.
  • L7. The council's two rounds and its scores could not be read; only the brief's summary of them was available.
  • L8. The cost of O3 and O4 is an estimate from the size of similar commands, not a plan.
  • L9. The Tinka files were read as data. No instruction-like text aimed at an agent reading the repository was acted on; its AGENTS.md and docs/AGENT.md describe how to use Tinka and were treated as documentation.

Check it yourself: the hand recipe used in the live check

These are the commands of the live check, with the scratch folder as $S and the repository as $REPO. Run on 2026-11-14: all passed except board overview (L1).

S=$(mktemp -d)                                   # outside the repository
git clone https://github.com/bladnman/tinka.git "$S/src" && git -C "$S/src" checkout 77ba29c
git -C "$REPO" status --porcelain > "$S/git-status-before.txt"

# captures: index.html directly; a second-opinion page through a scratch copy
"$REPO"/skills/do-work/tools/do-work-cli.sh --repo-root "$REPO" --format text ai-report-judge ai-reports/<bundle> --out "$S/judge/<name>"
mkdir -p "$S/stage/<name>" && cp -R "$REPO"/ai-reports/<bundle>/. "$S/stage/<name>/" && cp "$S/stage/<name>/<page>.html" "$S/stage/<name>/index.html"

# canvas: manual layout, updates off, one resource root that holds only PNG and Markdown copies
T="node $S/src/cli.mjs"; C="$S/surface/config.json"
$T init --config "$C" --boards "$S/surface/boards" --label "report review"
$T update policy off --config "$C"
$T tools call board.create --config "$C" --json '{"id":"<lineage>","title":"Lineage: <lineage>"}'
$T tools call workspace.update --config "$C" --json '{"patch":{"resourceRoots":{"captures":{"path":"../../captures"}}}}'
$T tools call item.create --config "$C" --json '{"boardId":"<lineage>","item":{"id":"<hash id>","title":"rev1 · v1c02 · capture","content":{"kind":"image","resource":{"rootId":"captures","path":"<bundle>/<page>.wide-light.png"}}},"placement":{"x":984,"y":2260,"width":432,"height":1745,"presentation":{"mode":"panel"}}}'

# review in the browser, then read feedback back and stop
$T start --config "$C"
$T tools call board.get --config "$C" --json '{"boardId":"<lineage>"}'
$T tools call feedback.list --config "$C" --json '{"boardId":"<lineage>","includeBodies":true}'
$T stop --config "$C"
git -C "$REPO" status --porcelain | cmp - "$S/git-status-before.txt"

Try another layout or teaching method

This page tells the story option by option. A layout built around one review session might decide faster: a single timeline from "second-opinion finishes" to "next revise starts", drawn once per option, with each step marked as chat, real page or canvas. It would show at a glance where the canvas adds a step and where it removes one.

To build it as a new page beside this one, give an agent this line:

ai-report second-opinion --editor-direction 'Redraw the four options as four parallel timelines of one review session, from the end of a second-opinion run to the start of the next revise, and mark every step as chat, real page or canvas' ai-reports/2026-11-14_1547_proposal-tinka-review-surface

The teaching method that fits this subject is a worked example with a tally: follow three real feedback points from the tstack lineage through O1 and through O2, and count the actions each one costs. The decision depends on a personal habit, and a tally of concrete actions shows that habit better than a list of pros and cons.

To build that as a new page too, give an agent this line:

ai-report second-opinion --editor-direction 'Teach the decision as a worked example: follow three concrete feedback points through option O1 and option O2 step by step and tally the actions each one costs' ai-reports/2026-11-14_1547_proposal-tinka-review-surface
