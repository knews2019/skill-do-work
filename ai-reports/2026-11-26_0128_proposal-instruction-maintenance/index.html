Let the integrator update the request.

Step 6 tells a builder in a separate checkout to edit a request that only the integrator may change. The builder can return its evidence in the handback. A second, independent cut would skip drafting a knowledge-base offer when nobody can answer it.

O1 · First priority

Let the integrator mark the phases complete

Benefit
A builder in a separate checkout knows to return its plan, changes and checks in the handback. The integrator checks the evidence and updates the request.
Cost
Narrow one sentence in the implementation instructions and name the evidence in the handback template.
Risk
A copy into the request can silently fail. A previous review caught exactly that. Verify the actual checkboxes before qualification.

O2 · Second priority

Defer the unattended lessons draft

Benefit
When an unattended run has no way to ask, it can record the lessons as pending before composing an inbox document.
Cost
Move the existing fallback ahead of drafting. Limit the draft and prompt checklist to interactive offers.
Risk
A run wrongly classified as unattended could hide an offer someone wanted. Preserve the full preview and consent step whenever someone can answer.
kb-lessons-handoff.md · line 121
O3 · Defer both

Keep the current wording

Benefit
No edits or migration work.
Cost
Builders must reconcile the two writing instructions. A literal reading still calls for an unattended draft.
Risk
The next integrator may receive a request edit on a branch whose queue changes must be rejected at merge.
fan-out-reference.md · line 79

Recommendation. Choose O1 first. An archived handback shows the proposed division of work already succeeding. O2 removes a draft that cannot be used on one branch of the procedure. The archive confirms the pending outcome, but gives no measurement of time spent writing such drafts.
