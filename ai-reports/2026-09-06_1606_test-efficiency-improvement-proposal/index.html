Signals lose their exit status

The Python wrapper passes a negative subprocess return code directly to sys.exit. A self-SIGTERM child produced JSON status −15 but shell exit 241, rather than preserving signal termination or returning 143.

Fix: preserve normal and signal exits, forward cancellation to owned descendants, and verify cleanup on interruption. Only the exit-code defect was reproduced here; cancellation cleanup still needs a dedicated check.

How to accept an improvement

Performance evidence

Run the same selected scenarios at fixed concurrency on comparable snapshots. Record source changes, cache state, toolchain, CPU including child processes, and elapsed time. Use at least three repeated samples with median and spread. Count the work being removed: build invocations, Git processes, tree walks, or bytes hashed.

Measure profiling overhead separately. Report noisy or inconclusive outcomes honestly; do not claim a percentage from a single run. Reused-stage skips must be separated from actual execution speed.

Coverage evidence

Map old cases and assertions to their new locations. Introduce representative defects that the old tests detected and demonstrate failure after refactoring too. Keep real process tests for process behavior and real transaction tests for transactional guarantees.

Freshness and isolation are acceptance conditions: wrong binaries, mutated shared fixtures, and stale Git data must not pass. Required fast/heavy gates still run according to the repository workflow.
