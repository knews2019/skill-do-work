Board · Durations view · successor to REQ-278

The label face is unbounded. Bound it, don't survey it.

Recommendation: bundle one font and pin the labels to it (O1). It is the only option that closes both the vertical and the horizontal exposure at once, keeps every existing Go test meaningful, and needs no measurement anyone has to repeat.

Solutions report, written 2026-08-19 after REQ-278 was cancelled for scoping the work as cross-OS font measurement. Every number quoted below is read from this repo's own source and comments; none was re-measured for this report.

The actual constraint

The Durations view draws each sample's label as an SVG <text> element. Two numbers govern whether those labels collide, and both are hard-coded measurements of one particular typeface:

NumberWhereWhat it claimsFailure mode if wrong
7.15 durations.go:250 units of width per label character — the collision model's upper bound Visible. Under-estimate and two labels overprint — the exact defect UR-051 was raised to fix.
13 board-durations.js:60 vertical pitch between the two label rows Not visible. Rows overlap in line box, which is padding; the ink stays clear. What breaks is the clearance claim, not the render.

The largest label box ever measured here is 12.9631 units against that 13-unit pitch — 0.037 of slack. Every sample was taken in a Linux container, and board.css:65 ends --font-sans in the open sans-serif generic, so nothing constrains what a Mac or Windows machine resolves. The repo's own comment already says so, at durations_test.go: "What this constant is NOT is a supremum over the face space."

The horizontal axis is the dangerous one, and REQ-278 never mentioned it. A wider face than 7.15 units per character causes real overprinting; a taller face only invalidates a claim. Any fix that addresses only the pitch leaves the visible failure in place.

There is a second structural fact that shapes every option below: label placement runs in Go, at generate time, before any browser exists. planDurationLabels (durations.go:481-518) assigns each sample a row and an anchor side using the 7.15 constant. It cannot measure the font that will resolve at view time, because at that moment there is no font. Runtime measurement therefore is not a tweak — it means moving or duplicating that algorithm.

Options

Ordered by how much of the problem each one actually closes.

O1 · Recommended

Ship a font and pin the labels to it

Embed one .woff2 next to the existing assets — generate.go:22 already does //go:embed web/template.html web/board.css web/*.js, so an added file needs one glob and no new machinery — declare it as an @font-face, and set .durations-mark-label (and the tick and axis-title faces, which have the same exposure) to that family with a concrete last-resort fallback rather than the open generic.

Both constants then describe a typeface this project ships. They are measured once, on any machine, and they are true everywhere the board is ever opened. The whole class of "what does Segoe UI draw" questions stops existing rather than being answered.

Closes
Both axes. Width and box height become properties of a known file.
Cost
15–40 KB embedded, depending on the face and subsetting. One @font-face block. A licence check on whatever face is chosen.
Locks in
Chart labels stop matching the reader's OS UI font. On the chart specifically, that is arguably an improvement — it is a data graphic, not chrome.
Test impact
None negative. Every existing clearance test keeps its meaning and finally gets a defensible referent.
O2

Move placement into the browser and measure for real

Delete both constants. Render the labels, measure each with getComputedTextLength() and getBBox(), then run collision and row assignment in JS against real extents. Correct by construction on any face, on any OS, forever.

Closes
Both axes, permanently, with no constant to go stale.
Cost
High. A tested Go algorithm moves into JS. A measure-then-place pass means the chart reflows after first paint unless it is rendered offscreen first.
Locks in
The Go test suite loses its grip on placement — durations_test.go's row-assignment, remainder-count, and clearance tests all assert against the Go model. Replacing them needs a headless browser in the test path. maintainer-verify.sh runs Go throughout and one optional Node lane it skips when Node is absent; it has never needed a browser.
Note
This is the textbook-correct answer. It is also the one that trades a cheap, fast, deterministic test suite for a slow, flaky one.
O3

Go plans, the browser repairs

Keep Go's placement as-is, and add a small JS pass after render that measures actual extents and hides any label that genuinely collides. The Go model becomes a hint; the browser has the final say.

Closes
The visible width failure. The pitch claim stays unproven.
Cost
Moderate, and it is additive — nothing existing is rewritten.
Locks in
Two places decide one thing. The remainder count ("+N more") computed in Go stops agreeing with what the browser actually drew, so either that number becomes a lie or it has to be recomputed client-side too.
O4

Widen the pitch to a defensible upper bound

Stop deriving the pitch from measured metrics and set it from a ratio no realistic UI face exceeds — 1.5 em, or about 16.5 units at the 11px label size — with the constant's comment saying it is a bound, not a measurement.

Closes
The vertical claim only, and only for faces under the chosen ratio.
Cost
Lowest of any option here: one number and one comment.
Locks in
Leaves the width exposure entirely — the failure that is actually visible. It also spends vertical budget REQ-265 just narrowed to 0.10 units against the Panel B ceiling, so raising the pitch on its own is not free.
Verdict
Not sufficient alone. Reasonable as a same-commit companion to O1.
O5

Draw fewer labels

Replace per-sample direct labels with a hover or focus readout, or a side table, and let the collision problem stop existing.

Closes
Everything, by deleting the feature that has the problem.
Cost
Large, and it walks back what UR-051 asked for — the labels were the point. It also costs the keyboard and print paths, which a hover readout does not serve.
Verdict
Listed for completeness. Recommend against.

Why O1 over O2

O2 is more principled and I would pick it in a codebase that already ran a browser in its test suite. This one does not. maintainer-verify.sh is fast, deterministic, and shell-and-Go only; every measurement in durations_test.go got there by someone running Playwright by hand and pasting the number into a comment with the build recorded beside it. O2 would make that manual ritual mandatory and continuous. O1 makes it unnecessary — one measurement, one file, one time.

Put differently: O2 removes the constants by making them dynamic. O1 removes the uncertainty by making them true. The uncertainty is what you actually objected to.

If O1 is chosen, the REQ is roughly this

  • Pick and subset a face with a permissive licence — Inter, Public Sans, and Source Sans 3 are all OFL and metrically documented. Subsetting to digits, latin, and the handful of punctuation the labels use keeps it small.
  • Embed it, add the @font-face, and point .durations-mark-label and .durations-axis-title at it — both sit on --font-sans today. .durations-tick is on --font-mono, whose stack ends in the open monospace generic and carries the same exposure; decide deliberately whether it gets a bundled mono in the same pass or is left as a known gap. Leave the rest of the board on the existing stacks — the chart is what needs determinism, not the cards.
  • Re-measure the width supremum and the box height once against the bundled face, and rewrite the comment blocks in durations_test.go so they stop hedging about an open face space and instead name the file the numbers describe.
  • A lock-in that fails if the chart label stack ever regains an open generic fallback — that is the defect, and it is a one-line grep-shaped assertion.
  • bash _dev/tests/maintainer-verify.sh exits 0.

Sources read for this report: durations.go, durations_test.go, board-durations.js, board.css, generate.go, and the cancelled REQ-278. Nothing was rendered or re-measured — the option costs are engineering judgement, not measurements, and the 15–40 KB and 1.5 em figures are estimates.
