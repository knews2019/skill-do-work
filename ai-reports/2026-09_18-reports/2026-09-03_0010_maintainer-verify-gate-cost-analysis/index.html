The Maintainer Gate: What Six and a Half Minutes Buy

2026-09-03 · target: _dev/tests/maintainer-verify.sh at commit ca5dacbb · evidence mode: non-visual

Verdict. The gate is a reasonable release check and an unreasonable per-REQ check, and today it is both. Of its 6.5 minutes, about 40% is the same work run two or three times: the board's JavaScript probes execute in three layers, and the aggregate suite runs its sub-suites one after another on an eight-core machine. The bigger cost is outside the script. The work pipeline runs the whole gate twice per REQ (baseline before dispatch, again at Step 6.5), and 167 REQ commits landed in the last 14 days. That is on the order of 30 hours of gate wall-clock in two weeks. First fix: run it once per REQ. Second: a path-scoped fast lane. Third: dedupe the probes.

Why the gate exists at all

Before REQ-187 (2026-08-15) a hand-back meant coordinating five command families by hand, and nothing proved shell and both Go modules together. REQ-187 made one script the single source of truth and the justfile delegate to it.

The per-REQ cost came five days later. REQ-283 archived green on area-scoped tests while this gate had been red for three REQs. REQ-309 (2026-08-20) made the pipeline run the whole gate per REQ instead of only the changed area's tests. That is the rule the report proposes to keep, but to satisfy with a recorded green revision plus a fast lane instead of two full runs.

Underlying technology

Orchestrationbash with set -euo pipefail; a just recipe wraps it. The self-test replaces tools with shell shims on PATH.

GoGo 1.26.1: gofmt, go vet, go test -count=1. Both modules use only the standard testing package; queue-kanban's one dependency is the goldmark Markdown parser. Subprocess cases re-execute the test binary with os/exec.
JavaScript probesNode 22. The board client is assembled from web/*.js and piped to Node on stdin, one process per probe, because the assembled client exceeds Linux's per-argument limit.
Browser laneHeadless Chromium launched with --remote-debugging-pipe; the test speaks the DevTools Protocol over that pipe. No Playwright.
Contract predicatesgrep and 26 Python 3 heredocs inside the bash file, parsing Markdown sections by regex.
Fixturesgit 2.50 throwaway repositories under mktemp -d, one per sub-suite process and per Go test that needs one.

Bar widths are seconds on one shared scale (280 s full width). The sub-suite bar's amber part is the serial-order cost: run standalone the 14 sub-suites sum to about 160 s, and the longest single one is 60 s.

The JavaScript probes run three times

There are 55 TestJavaScriptBehavior* tests. Each spawns Node with the assembled board client on stdin, about 1.2 s apiece.

  1. Ordinary run (≈70 s). Node is on PATH, so they execute.
  2. Zero-probe meta-tests (43 s + 16 s). Two tests re-execute the test binary over the whole probe set to prove the strict guard rejects an all-skipped run.
  3. Strict lane (51 s). The script runs the same probes again with the guard marker set.

Layer 1 is the coverage. Layers 2 and 3 exist to prove a skip cannot be mistaken for green. That property is worth one cheap test, not 110 s.

4 · Is it overkill?

keep The checks themselves

ShellCheck, gofmt, vet, and real behavior tests for two Go tools and 18 shipped shell scripts are what a release gate should be. 973 Go tests plus 110 shell cases for a suite this size is proportionate. The 6 s of lint is free.

overkill Running it twice per REQ

The pipeline runs the identical argv before dispatch and after integration so an unrelated failure can be attributed. A recorded green revision hash does the same job: if HEAD equals the last green hash, the baseline is known without running anything. This alone halves gate time and touches no test.

overkill One tier for every purpose

There is no fast lane. A one-line prose edit to an action file pays for 211 s of board tests and 39 s of CLI tests that cannot be affected by it. -count=1 disables Go's test cache everywhere, so untouched packages are never free.

overkill The growth curve of the contract file

contract-regressions.sh was 162 lines 60 days ago, 940 at 30 days, 4,757 at 14 days, 8,417 today. 197 FAIL predicates and 26 embedded Python programs pin sentences in the action files. Its wall-clock cost is small; its maintenance cost is the subject of the 2026-09-02 orchestrator report, which found it is what keeps deletable prose in place.
