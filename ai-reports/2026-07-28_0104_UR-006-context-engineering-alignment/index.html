How it works

Progressive disclosure: the skeleton loads, the detail waits

The pattern already existed (work.md ↔ work-reference.md); the batch applied it to the three worst offenders. Each split enforced a two-way contract checked by grep receipts: every moved section is pointed at by name from the step that consumes it (no dangling pointers), and every companion section has an inbound pointer (no orphans).

Fidelity was proved by diffing the moved blocks against git show HEAD — byte-identical apart from heading levels. Relocation, not redesign.

Each REQ, one level deeper

REQ-027Earned sections, plus a ratchet — the root-cause fix, and the gate for the splits

The maintainer template treated Rules / Common Rationalizations / Red Flags / Verification Checklist as near-mandatory, so 24–33 of 43 action files carried all four — mostly generic filler. A previous release (0.123.2) deduped once and the boilerplate grew back, because the template still asked for it.

The fix is a test, not a vibe: a section is included only if you can name the specific failure it prevents and where it happened; “generic engineering advice a capable model already follows” is an explicit non-reason. A new check in _dev/tests/contract-regressions.sh fails any new action file whose Common Rationalizations table contains no do-work-specific noun (REQ, UR, queue, frontmatter…), with the 42 existing files grandfathered via a baseline array.

Wrinkle worth knowing: a naive case-insensitive noun pattern was useless — -i makes “REQ” match inside “required”. The check splits into a case-sensitive pattern for REQ/UR- and a case-insensitive one for the rest. Red→green was proven with a throwaway generic action file that made the suite fail, then pass once rows named real machinery.

REQ-025State each shipped guard once — 13 restatements of one commit guard become 1 + pointers

Three guards lived in many places: the git add -A/hook-bypass commit guard (13 mentions across 7 files, 5 inside stray-check.md alone), prompt-injection doctrine (inlined in three actions despite crew-members/prompt-injection.md existing to be JIT-loaded), and “this action is read-only” (3–5 restatements per file in three actions). Each now has one canonical home; every other site is a one-line pointer. Net −440 words across 12 files.

Adversarial review earned its keep twice: the first pass left capture.md's Step 0 still paraphrasing the injection doctrine it claimed to have deduped, and the “pointers” at three sites still named the literal --no-verify flag — re-exposing the mechanism the canonical home owns. Both fixed; the post-fix grep shows the flag surviving in exactly one file (actions/commit.md).

Judgment call preserved: bkb.md keeps two injection load-steps because its triage and ingest sub-commands are independently invokable — collapsing to one would silently unguard a real ingestion path. “No behavior change” outranked the literal count.

REQ-026next-steps.md: intent over enumeration — 1,741 → 383 words; the biggest always-read cut

The file was 47 hard-coded “After X, suggest Y” blocks, read after every action. It's now a stated intent (infer 2–3 suggestions from actual queue state), a few format constraints, one anchor example, and a 6-row table of the genuinely non-obvious cases (pipeline interrupted vs completed, reserve, capture-requests, clarify with pending answers).

The keeper test that emerged: a row survives only when the action's own output doesn't announce which state it left the queue in — so an agent inferring from intent alone would plausibly pick the wrong branch. tidy-repo was considered and rejected on exactly that test: its output says “plan-only” or “executed”, so no table row needed.

REQ-028Crew files trimmed to opinions — 6,737 → 4,237 words; security dedup resolved first

Per-line keep test: a line survives as (a) a deliberate project preference or (b) tied to do-work machinery. “It's true” is not a reason. backend.md lost 75%, frontend 61%, testing 60%; security.md and ui-design.md have structural floors — their sections are hard-cited by name from code-review.md and ui-review.md, so they were trimmed, not gutted. All six JIT_CONTEXT load contracts verified byte-identical.

Nothing said once ended up said zero times: the two frontend security bullets not already in security.md (Vue/Angular innerHTML naming, rel=noopener) moved there before the frontend copies were deleted.

Insight from the pass: specificity is a proxy for opinion — “bcrypt cost 12+” survives where “use appropriate HTTP status codes” doesn't, even though both topics are well-known.

REQ-029Split ai-report — 7,541 → 5,477 + 2,339 on demand; earned-sections pass found nothing to cut

Image Generation Backend, the SVG data-viz rules, the report design rules, the before/after toggle implementation, and the output-format template moved to ai-report-reference.md (this very report was produced under the split regime — the reference sections loaded only when their steps ran). Two-way pointer check: 8 pointer sites, 5 companion sections, zero danglers/orphans.

An honest zero: applying REQ-027's earned-sections test row-by-row deleted nothing — all 63 rows/bullets across the four sections name specific failure modes (the file:// blank-screenshot bug, injection→RCE via the agentic backend). A narrow, single-purpose action can already be fully earned; the test's job is to confirm, not to force deletions.

REQ-030Split pipeline — 7,471 → 4,719 + 3,084 on demand; found a real routing bug on the way

The state-file schema and every output rendering (status blocks, the three-format completion report, continuation notice, help menu) moved to pipeline-reference.md. The action file keeps decision logic plus the state file's lifecycle — including the discovery that the REQ's phrase “when it is deleted” assumed a deletion step that doesn't exist: pipeline.json is never deleted, it's set inactive and left as a historical record.

Discovered task: tracing the help-menu routing revealed do-work pipeline help never reaches the Help Menu at all — Step 1 buckets “help” as request text and tries to start a pipeline named “help”. Pre-existing, out of scope for a relocation, recorded for a follow-up fix.

Review add-on: two ADRs (adr-001, adr-008) stated the templates lived inline — made false by this split, fixed in the same commit, matching the precedent set when this companion was re-inlined in 0.76.0.

REQ-031Split capture — 5,505 → 3,913 + 1,682 on demand; all five worked examples deleted

The REQ/UR templates and schema-alias table — a hard contract read by work.md, roadmap.md, and the Kanban board's parser — moved verbatim (diff-proven IDENTICAL) to capture-reference.md, opened at Step 5 or the Step 2 addendum branch.

The examples decision: all five worked transcripts deleted, none relocated. Each was read against the bar “does it encode a judgment the templates don't?” — the strongest candidate, Complex Multi-Feature Request, sliced 1:1 feature→REQ with no depends_on at all, failing to demonstrate the one thing that would have earned it a home.

Acceptance test that matters: an end-to-end throwaway capture (UR-999/REQ-999) run from the split files produced a correctly paired, correctly UTC-timestamped UR+REQ — then was deleted.

Same day, separate story

REQ-018 — Concurrent-orchestrator lock guard (UR-005)

Completed 80 minutes after the batch: the fix for the 2026-07-01 incident where two sessions ran do-work run on one tree and the second archived the first's in-flight build with a hollow paper trail. The work loop now takes a heartbeat lock (do-work/orchestrator-lock.json); a second orchestrator gets a three-choice prompt (proceed / take over / abort) or a safe refusal when non-interactive, and stale locks self-heal after 45 minutes. Two adversarial review rounds reshaped it — “proceed anyway” originally killed the session it promised to spare. It earns its own report: do-work ai-report UR-005.

Open threads & lessons

Carried forward

  • do-work pipeline help starts a pipeline instead of showing help — Step 1 needs “help” as a reserved keyword (found by REQ-030).
  • frontend.md and ui-design.md both state the prefers-reduced-motion rule — same duplication shape REQ-028 just resolved elsewhere (found by REQ-028).

What the batch taught

  • Structural fixes beat trims: the last dedupe grew back; this one changed the template and added a ratchet, the same move that paired the SKILL.md diet with its word budget.
  • Re-derive audit numbers with fresh greps before editing — the concept can be duplicated even where the literal string isn't.
  • An earned-sections audit that deletes nothing is a valid outcome — confirm row-by-row, don't assume every file needs trimming because the rule now exists.
