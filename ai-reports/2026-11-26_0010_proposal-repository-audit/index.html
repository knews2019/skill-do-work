Where the checkout and its tools disagree

1 · Incorrect diagnostic

Doctor mistakes a bullet format for proof of completion

REQ-611 names changed scripts in a numbered summary. REQ-612 uses ordinary sentences with file paths later in each bullet. Both recorded commits changed those scripts. Doctor only extracts a path from a bullet that begins with a backticked filename, then uses that path list to decide whether implementation evidence exists.

Fix. Distinguish an absent summary from an unrecognized path format. Check the two real formats alongside an empty summary and a bookkeeping-only completion before reclassifying historical records.

3 · The restart prompt points to finished work

The paste-ready first block tells a maintainer to resume REQ-748. Its archive record says completed on November 19, and the queue and working directories hold no request Markdown. 4 · Core and board have different Go prerequisites

The README describes Go 1.24 or a prebuilt binary for the suite. The board guide extends its local-Go requirement to core. Core can fetch a verified binary on supported hosts, while board launchers build a separate module declaring Go 1.26. State both requirements together in the README and correct the board guide and action.

The toolbox code-review rubric points to its local “Simplicity First” section. The core version includes an “Earned defense” paragraph that the toolbox copy lacks. If the rule applies to both activities, point the review rubric to the core owner and check the other callers before retiring the copy. Preserve any intentional package-specific guidance.

Limits and open questions

This audit covers repository structure, selected entry points, packaging and maintainability. Verification used local commands and two sampled commit diffs. The full maintainer gate, remote release jobs and cross-platform execution were outside this pass. The 34 other hollow-completion flags need individual review before editing archive records.

Q1. Do users unpack the source archive to run the root recipes directly? That determines whether to exclude the root justfile or maintain a smaller archive interface.

Q2. Should toolbox reviewers share core’s “Earned defense” rule? If they need a distinct policy, document that difference at the review rubric.
