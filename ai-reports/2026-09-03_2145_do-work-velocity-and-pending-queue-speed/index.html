The queue's shape

Twenty-two of the 37 pending REQs are ready now; their dependencies are archived. The other 15 sit behind four chains. Most are two or three deep and clear as their head lands. One is different: REQ-502 through REQ-510 is a nine-step serial rewrite of the work loop (the read-only advance command, then selection, gates, archive and finalize moved behind it, then capture templates and work-reference sweeps), with REQ-486 behind it. Every link is a rule change that depends on the previous one, so it is genuinely serial. At the recent median that chain alone is about 11 hours of pipeline time, and it is the queue's critical path however many builders run.

Draining everything else is throughput-bound instead: 27 REQs at 65 minutes is about 29 hours serial, and the ready set can be built in parallel under one orchestrator. Shortening the gate takes roughly a third off both figures. Starting the advance chain early, in its own lane, takes the critical path off the end of the drain. Why the queue refills

In the 30 days to 22:00 today the pipeline created 395 REQs and archived 391. It shipped 439 releases and 1,863 commits in the same window. That is not slow. The queue has stayed near 40 the whole time because intake tracks output, and it does so because the pipeline is its own largest customer: 130 of the 391 archived REQs were minted by a review handback, 182 were addenda to a prior REQ, and only 21 carried impact-critical. The 2026-08-20 report measured the same equilibrium at 145 of 298 REQs ever written; the share has not moved.

The mechanism is the contract suite. _dev/tests/contract-regressions.sh is 8,479 lines of assertions that pin specific sentences in the action Markdown: about 200 grep predicates and 25 embedded Python programs, each added when a REQ fixed a behavior that existed only as a sentence. When a later REQ edits prose that disagrees with a pinned sentence, the gate goes red, the review names the discrepancy, and the pipeline mints a REQ to reconcile the two. That REQ edits more prose, which meets more pins. The pins are not where the gate's seconds go; the 00:10 analysis measured them at about 9 s against 140 s for the 14 sub-suites that build throwaway git repositories. They are where the REQs come from.

Two brakes exist and neither is engaged. REQ-531 (review findings below impact-critical stay in the report, the maintainer captures by hand what is worth building) is the one that closes the tap: 126 of the 130 review-born REQs this month were below critical. It waited on REQ-548 (repairing the gate's broken pipe) until 21:46 and has been claimed since 21:47. The second is UR-100's line-count ratchet on the contract file: the ceiling was 8,417 lines on 09-02, REQ-519 that carried it was cancelled, and the file is 62 lines over with no ratchet in place. REQ-539 carries it now, behind REQ-538.

Every one of the 40 open REQs is do-work working on do-work. Seven batches: orchestrator simplification (8), the two-tier gate (5), non-blocking orchestration (4), the Go command platform (4), today's validate feedback (3), recovery never traps (2), close the tap (1). Nothing in the queue or the archive this month came from a project that uses the skill.

Lessons learned today

What this day taught about making the queue move, written so a session that has none of this context can act on it. Each lesson names the evidence and the rule that follows from it. Added at 22:25.

Gate and tests
#LessonEvidence
L1A tier is not a speedup until the heavy tests are excluded before they start. Skipping inside a test still pays its fixture setup. Exclude by test selection (run pattern or knob checked at the top of the test), then measure.REQ-537: fast 629 s, heavy 631 s. Codex profiling: the JavaScript probes "skipped" after doing most of their setup, so the fast tier still took 109 s.
L2A time budget is a program, not a sentence. The gate times every file, logs the durations with the number of concurrent gate processes, and fails the fast tier over 30 s. Prose limits are never enforced; suites grow back.UR-100's ceiling was 8,417 lines; the file was 8,479 with no ratchet. First budget run caught generate_test.go at 30.35 s; reusing its fixture brought it to 7.30 s.
L3One gate per machine. The same tier measured 301 s, 363 s and 641 s on the same day. Under load every timing is wrong, including the budget. Before starting a gate, look for another one running.At 22:15 two contract-regressions runs and one go test were executing at once, from two sessions.
L4Delete before you skip. A meta-test that re-executes the whole binary is replaced by a unit test of the guard it protected. A sentence pin whose comment names no incident REQ, or whose target is not a shipped file, is deleted, not moved to heavy.Codex diff: two RejectsZeroProbes meta-tests (41.8 s and 16.1 s) became one table-driven test of strictProbeGuardFailed.
L5The gate runner only helps if something starts it. It has existed since 0.266.9; nothing launched it, so every REQ paid two gate runs. Start it by hand until REQ-542 lands.Two runs at 629 s are about 21 of the 65-minute median REQ.
L6A change to the gate lands in place, never through the pipeline. The pipeline would run the gate two or three times to ship a change to the gate.UR-104's batch constraint; REQ-537 landed at 8d9d1bb that way.
Queue and coordination
#LessonEvidence
L7A batch order is not a dependency. Capture encodes "do A1 then A2" as a depends_on chain. Before accepting a chain, ask whether the dependent reads the other's output; if not, drop the link so builders can run in parallel.REQ-540 and REQ-542 waited on REQs whose files they never touch; dropping both raised ready work from 20 to 22.
L8A claim without a worktree is a stall, and unclaimed parallel work is a collision. Check git worktree list and do-work/working/ together. Only the maintainer releases another session's claim.REQ-538 claimed at 19:49 by a cloud session that went idle; a Codex worktree did the same cuts on its own branch.
L9Several sessions in one checkout must announce before touching shared files. Cross-session messages work; use them. Land with explicit paths, never git add -A.Four sessions touched this checkout tonight: the REQ-531 run, Codex, a report revision at 9d18e031, and this one. The other checkout asked by message before claiming REQ-267.
L10Two records of one duration disagree for known reasons; do not "fix" one to match the other. Log rows are written once and sometimes hand-rounded; frontmatter is re-stamped by crash recovery and measures only the last re-run. Say which is which.REQ-460 log 421 min vs frontmatter 20; 17 of 203 log rows end in :00Z. The two rows were later rewritten to the frontmatter values.
L11Two checkouts on one port kill each other's board. just run-kanban stops any queue-kanban on 8090 by design. Give each checkout its own port.The n1-weekly-signal-diff checkout took 8090 at 21:16 and killed this one's server; the browser looked "not opened".
L12Draining faster does not empty a queue that refills itself. Review-born REQs below critical are the intake; REQ-531 closes that tap and belongs beside the gate fix, not after it.395 created, 391 archived in 30 days; 126 review-born below critical.
L13Amend queued REQs by addendum, verify by parsing. Append a dated Addendum section with the user's words contained (blockquote plus a fence longer than any backtick run), record a "Resolved conflict" line when the original is superseded, and prove the edit with queue-kanban summary.Commit d00da469; the board parsed all four files, zero malformed.
L14When you delete gate work, keep its assertions. A test file can be dead as a gate step and still be the only home of a zero-hit guard. Before deleting one, grep it for the assertions it carries and re-home them in a fast file, or the guard is gone with the seconds.0.266.9 (5e0e166c) deleted _dev/tests/shipped-shell-thinness.sh as "no gate path executes"; the 2026-09-03 maintainability audit found the "every shipped .sh reaches do-work-cli" assertion now has no home. REQ-551 re-homes it in _dev/tests/audit-lockins.sh.
