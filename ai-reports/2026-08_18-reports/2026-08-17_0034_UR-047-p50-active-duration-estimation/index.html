P50 Active-Duration Estimation

do-work now prices every REQ before building it: a deterministic P50 forecast of active agent minutes, printed right after triage, with dependency-aware totals for multi-REQ runs.

Shipped & verified — all 3 REQs completed Reviews: 96% · 95% · 94%, zero important findings v0.193.6 → v0.195.2

What shipped

REQ-208 — The estimator

tools/estimate-p50.sh: an agent extracts a REQ's sizing signals (route, write-set size, browser/persistence/async work, …) and this script does the arithmetic — so identical signals always produce identical estimates. Rounds to 5 minutes, floors at 10, attaches low/medium/high confidence, echoes the dominant factors. A critical-path mode computes dependency-graph totals. A lazy-loaded companion, actions/estimate-reference.md, tells the estimating agent how to extract signals; the optional estimate: frontmatter block is documented in the schema, fully backwards-compatible.

REQ-209 — Work pipeline wiring

New Step 3.6 in the work action: right after triage — the first moment the route is real — the run ensures an estimate exists and prints it before planning starts. Estimates freeze once execution begins. REQs captured before estimates existed get one automatically at first selection. Multi-REQ runs print per-REQ minutes plus two labeled figures: total effort and critical path. Estimation never blocks and never asks.

REQ-210 — Verify recalculation

When verify-requests materially changes a REQ while applying fixes, it refreshes that REQ's estimate in the same pass — a repaired scope never carries a stale price. Untouched REQs keep their estimates byte-identical; claimed and archived estimates stay frozen; read-only revalidation mode never touches them.

Problem and change

Before this work, the queue's only sizing signal was effort_estimate: trivial | normal — a deliberate two-value triage chip with a schema comment explicitly fencing off "an estimation system." There was no way to answer "how long will this batch take?" before committing to it. The change keeps that fence honest instead of quietly breaking it: the chip stays two-valued, the new estimate: block is a separate field, and the amended schema comment states the one bridge between them (trivial ⇒ floor estimate, no signal extraction). The core design split makes forecasts trustworthy: judgment stays with the agent, arithmetic goes to a shipped script — so estimates are explainable (the basis list), reproducible, and regression-testable.

Deliberately excluded

  • No P80 or other percentile fields — fenced in the script header, reference, and schema
  • No calendar-time promises — active agent minutes only; user wait, pauses, and queue time are excluded by definition
  • No actual_active_minutes — no pause-aware timing exists, and claimed_at−completed_at subtraction is forbidden as wall-clock contamination; v1 is documented as a pure-prior estimator
  • No board changes — verified the board's YAML parser tolerates the nested block as-is

How it works

Hand-authored diagram, derived from the shipped implementation.

The spec's own worked example, run live

$ tools/estimate-p50.sh --route C --write-set 12 \
    --browser --persistence --full-suite
p50_active_minutes: 125
confidence: medium
basis:
- Route C
- 12-file write set
- browser evidence
- persistence changes
- full-suite verification

The scoring table was calibrated so the spec's presentation example prices at exactly 125 — the spec is literally one of the lock-in tests.

Dependency graph: total vs critical path

$ tools/estimate-p50.sh critical-path \
    REQ-208:85 REQ-209:60:REQ-208 REQ-210:25:REQ-208
total_estimated_effort_minutes: 170
critical_path_minutes: 145

Total sums every branch; critical path follows the longest dependency chain (REQ-209 and REQ-210 both wait on REQ-208 but run in parallel with each other). Cycles are rejected, unknown (archived) dependencies cost zero.

Value delivered

Plan before committing

A queue or UR now answers "how big is this batch?" up front — per-REQ prices plus the two numbers that matter: total agent effort and the critical path your wall-clock actually follows.

Honest by construction

P50 means roughly a 50% chance of finishing within the estimate — documented everywhere it appears. Active minutes only; forecasts never become deadlines, never gate execution, and freeze once building starts.

Auditable and testable

Every estimate carries its basis. The arithmetic lives in a script with a registered lock-in suite, and both action wirings are contract-pinned — deleting the estimator or its pointers fails the test suite.

Near-zero cost where it's worthless

Trivial and plain Route A REQs take a short-circuit to the floor estimate without loading the reference file — overhead lands only where estimates carry information.

Verification method

This container carries 41 pre-existing environment failures in the full maintainer suite (missing just, tar/gzip exec, stat-mode probes — all in installer/updater behavior tests untouched by this work). The regression gate used throughout: record the FAIL set before any change, then require the post-change FAIL set to be byte-identical. It was, after every REQ. The new estimator suite runs inside the aggregate contract suite and passes; ShellCheck 0.11.0 at warning severity is clean across all tracked shell files. The estimator's determinism, rounding, floor, graph math, error paths, and print-only guarantee were exercised hands-on by the independent reviewers, not just by the suite.

Dogfooded on its own build

The three REQs carried hand-derived estimate blocks from capture (85 / 60 / 25 minutes — 170 total, 145 critical path), the work run printed each estimate before building, and REQ-208's estimate was recalculated (75 → 85) when a verify-requests repair materially grew its scope — exercising the exact lifecycle the feature defines. Honest gap, by design: actual active minutes were not recorded, because pause-aware timing doesn't exist yet and deriving actuals from wall-clock timestamps is exactly what the spec forbids.

Lessons and open questions

Lessons recorded in the archive

  • Calibrating the scoring table to the spec's own worked example turned the spec into a lock-in test.
  • The new contract pin caught a real bug before shipping: the test-suite path resolver sent bare tools/ paths to the repo root.
  • Restatement sweeps must follow the shape you changed, not the file you changed — the pipeline's step list was restated in three other places.
  • grep needs -- before data needles; a pattern starting with - parses as options (now linked from the shell prime).

Deferred to first real use
