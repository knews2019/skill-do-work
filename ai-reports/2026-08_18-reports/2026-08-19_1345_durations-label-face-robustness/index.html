5 · Options

Ordered by how much of the problem each one closes. The small diagram in each is the same pipeline as section 2, with the edge that option changes drawn in colour.

O1 · Recommended, not chosen

Ship a font file and pin the chart labels to it

Embed one subset .woff2 beside the assets generate.go:22 already embeds, declare an @font-face, and point the label class at that family instead of at a stack ending in an open generic. Both constants then describe a file this project ships — measured once, on any machine, true everywhere the board is opened.

Closes
Both axes. Width and box height become properties of a known file.
Cost
15–40 KB embedded depending on subsetting, one @font-face block, one licence check.
Locks in
Chart labels stop matching the reader's OS UI font. On a data graphic that is arguably an improvement — it is the one part of the board where consistency beats native feel.
Tests
No loss. Every existing clearance test keeps its meaning and finally gets a defensible referent.
O2 · Chosen

Move placement into the browser and measure for real

Delete both constants. Render, measure each label with getComputedTextLength() and getBBox(), then run collision and row assignment in JS against real extents — the same thing this report just did to produce section 1.

Closes
Both axes, permanently, with no constant left to go stale.
Cost
High. A tested Go algorithm moves into JS, and the chart reflows after first paint unless it renders offscreen first.
Locks in
The Go suite loses its grip — the row-assignment, remainder-count, and clearance tests all assert against the Go model. Replacing them puts a headless browser in the test path; maintainer-verify.sh runs Go throughout plus one optional Node lane, and has never needed a browser.
Note
The textbook-correct answer, and the one that trades a fast deterministic suite for a slow flaky one.
O3

Go plans, the browser repairs

Keep Go's placement, add a JS pass after render that measures real extents and hides any label that actually collides. Go becomes a hint; the browser has the final say.

Closes
The visible width failure. The pitch claim stays unproven.
Cost
Moderate, and additive — nothing existing is rewritten.
Locks in
Two places decide one thing. The "+N more" remainder Go computes stops matching what was drawn, so it becomes a lie or has to be recomputed client-side too.
O4

Widen the pitch to a defensible bound

Set the pitch from a ratio no realistic UI face exceeds — around 1.5 em, roughly 16.5 units at 11px — with the comment saying it is a bound, not a measurement.

Closes
The vertical claim only, and only under the chosen ratio.
Cost
Lowest here: one number and one comment.
Locks in
Leaves the width exposure — the half that is actually visible, per section 4 — and spends vertical budget REQ-265 just narrowed to 0.10 units against the Panel B ceiling.
Verdict
Not sufficient alone. Fine as a same-commit companion to O1.
O5

Draw fewer labels

Replace direct labels with a hover or focus readout and let the collision problem stop existing.

Closes
Everything, by deleting the feature that has the problem.
Cost
Walks back what UR-051 asked for, and a hover readout serves neither the keyboard path nor print.
Verdict
Listed for completeness. Recommend against.

6 · Why O1 over O2

O2 is more principled, and I would pick it in a codebase that already ran a browser in its tests. This one does not. Every number in durations_test.go got there by somebody running Playwright by hand and pasting the result into a comment with the build recorded beside it. O2 makes that ritual mandatory and continuous; O1 makes it unnecessary — one measurement, one file, once.

O2 removes the constants by making them dynamic. O1 removes the uncertainty by making them true. The uncertainty is what you objected to.

7 · If O1 is chosen, the REQ is roughly this

  • Pick and subset an open-licence face — Inter, Public Sans, and Source Sans 3 are all OFL with documented metrics. Subsetting to digits, latin, and the few punctuation marks the labels use keeps it small.
  • Embed it, add the @font-face, and point .durations-mark-label and .durations-axis-title at it — both sit on --font-sans today. .durations-tick is on --font-mono, whose stack ends in the open monospace generic and carries the same exposure; decide deliberately whether it gets a bundled mono in the same pass or is recorded as a known gap.
  • Re-measure the width supremum and the box height once against the bundled face, and rewrite the comment blocks in durations_test.go so they name the file the numbers describe instead of hedging about an open face space.
  • A lock-in that fails if the chart label stack ever regains an open generic fallback. That is the defect, and it is a grep-shaped assertion.
  • bash _dev/tests/maintainer-verify.sh exits 0.
