Before and after · source shape

One runtime, smaller places to reason.

Before

web/board.js held core helpers, filters, cards, calendar, testing, detail, controls, clipboard, state, and boot in one 2,531-line authored unit.

  • Reviewing one behavior meant navigating unrelated regions.
  • Source-owner comments could point only at the monolith.
  • A green Go suite could still skip every JavaScript behavior probe.

After

board.js is a 68-line private IIFE/state/bootstrap shell. Eight raw closure fragments own cohesive responsibilities. A fixed Go manifest assembles them for both static and live pages.

  • Authored inventory is wildcard-visible; execution order is literal and reviewable.
  • The first production assembly matched the old runtime byte-for-byte.
  • Syntax, behavior reachability, marker shape, and static/live parity have separate tests.
How it works

The wildcard observes; the manifest decides.

That separation is the central drift boundary. Adding a file changes inventory evidence, but never silently changes browser execution order.

What cannot drift silently

A missing, extra, or duplicated fragment fails the authored-inventory test.

A manifest reorder fails literal order and monotonic-offset assertions.

A malformed or surviving placeholder fails raw-token, canonical-line, and post-assembly checks.

Static and live caller divergence fails exact assembled-byte parity.

Better or worse

Net better, with real maintenance rent.

BETTER

Failures are less likely to look green.

JavaScript probes have a counted strict lane; case-sensitive path mistakes are source-ratcheted; missing filesystem evidence is reported instead of dropped; static and live browser clients are compared at their caller seam.

BETTER

Ownership is narrower and more explicit.

Cards, filters, calendar, testing, detail, controls, clipboard, and core helpers now have distinct source owners. The board walker owns stray discovery; verification consumes structured evidence rather than recreating it.

BETTER

Lifecycle advice matches behavior.

Review, work archival, verify, and forensics now agree that a closed UR stays closed and only the exact review-generated shape is legitimate beneath it.

WORSE / COST

There is more structural surface.

One authored JavaScript file became nine. The assembler, fixed manifest, placeholder contract, and structural tests are permanent obligations even though browser behavior did not change.

WORSE / COST

Some tests couple to source shape.

Exact marker lines, assertion forms, and literal manifests catch real drift, but careless accumulation can turn the suite into a brittle policy museum. Keep them incident-backed and mutation-proven.

WORSE / COST

The maintainer path is slower.

The canonical gate took about 70 seconds on this machine. That is acceptable for release handoff, not every edit loop; touched-area tests should remain the fast inner loop.

Prevent drift and useless work

Adopt a six-part admission test for every new rule.

The goal is not more tests. It is fewer independent truths and stronger evidence at the seams that matter.

Name one owner

Every alias list, status vocabulary, command inventory, fragment order, or filesystem detector gets one canonical owner. Other files point to or compare against it; they do not restate it.

Test the consumer seam

Exercise the path production uses: caller, route, assembled page, structured handoff, or full predicate. A helper-only test is insufficient when a wrong caller can bypass it.

Demand a surviving mutation

Before adding a guard, show the wrong implementation that currently passes. Then replay deletion, negation, duplication, wrong casing, or alternate data-source mutations.

Charge surface cost

A new file, parser, fallback, warning, or contract must name the incident that earned it. Prefer deletion, narrowing, or extending an owner over a new framework or scan.

Keep one release gate

Use focused tests while editing, then run maintainer-verify.sh once at handoff. New recipes and docs delegate to it; they do not copy its inventory or execute children twice.

Stop at dirty boundaries

Do not claim or archive a request whose pre-existing user edits would be folded into the implementation commit. Dependency and dirty-state visibility prevents progress that destroys provenance.

Useless-work rejection rule

Do not queue the work unless all four answers are yes: Is there a reproduced failure or accepted finding? Is the proposed owner canonical? Does a focused mutation prove the repair? Is the lasting surface cheaper than the failure it prevents? If not, keep it as watch evidence or delete/narrow an existing rule.

Lessons

The dangerous bugs were disagreements between two plausible truths.

Line shape is not token uniqueness.

A second raw placeholder at EOF survived when tests counted only marker-plus-newline. Raw uniqueness, canonical placement, and post-assembly absence are separate invariants.

Warnings are not structured evidence.

Verification could have parsed a human warning and stayed green. A direct test with only structured stray records forced the intended handoff.

A green local filesystem can lie.

macOS accepted capitalized Justfile paths. The lasting proof had to be source-case exact and deletion-resistant, not another local run.

Completeness needs its own channel.

Unavailable hotspot paths should not corrupt numeric ranking, but dropping them made an incomplete report look complete. Separate measured rank from missing evidence.
