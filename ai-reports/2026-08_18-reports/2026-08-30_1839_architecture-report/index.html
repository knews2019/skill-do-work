Changed since the last report

+ Go

VERIFIED The meaningful architectural change is a new shared command runtime. Version 0.245.0 introduced do-work-cli; 0.247.0 moved bootstrap, install, update, managed-section replacement, settings composition, manifest validation, and archive fetching onto it. Five shell entry points remain, but they are compatibility launchers over one Go engine. CHANGELOG.md:13-39

VERIFIED The other post-baseline movement is inside the board, not at a package boundary. Timeline calendar periods became trailing windows; finished boards then gained bound-aware windows and reversible stepping. Live cache hits also rebuild wall-clock-derived Timeline data without reparsing the tree. CHANGELOG.md:5-29 · CHANGELOG.md:41-47

Its package boundaries, queue lifecycle, knowledge split, board write-surface contract, export boundary, and one-releaser concurrency model remain present. Two prior statements no longer hold: the board is no longer the only compiled component or only Go prerequisite, and queue verification no longer reports ungated write-set overlap. System thesis

One product, four instruction packages, three Go modules

INFERRED The cleanest current model is two interacting planes. The instruction plane is the routed Markdown that tells an agent how to reason and mutate state; the execution plane is deterministic Go for operations where one parser, transaction, or output contract is safer than repeated prose and shell. Basis: four package routers remain the public interface, while three Go modules now sit under package-owned tool directories.

VERIFIED Core owns the durable request lifecycle. Its first-match router selects one action, while the UR preserves intent and the REQ accumulates requirements, decisions, implementation, review, lessons, and orientation. core SKILL.md:18-49

VERIFIED Board owns a compiled projection, not orchestration. It reads core’s records and routes board-shaped calls to one action; queue lifecycle changes stay with core. board SKILL.md:7-25

VERIFIED Knowledge owns two memory strategies and their trust boundary. BKB synthesis, lightweight memory, consolidation, interviews, and trusted prompts are routed together; transcript capture remains opt-in. knowledge SKILL.md:7-31

VERIFIED Toolbox owns optional repository-facing work. Reports, audits, presentation, inspection, and utilities are outside the REQ lifecycle and read sibling artifacts through literal relative paths. toolbox SKILL.md:7-45

The durable record

The files are the workflow state

VERIFIED Capture and execution stay separate. One capture creates a UR folder preserving exact input plus one or more linked REQs; it may clarify and decompose, but it does not start implementation unless the same invocation explicitly asks for both. README.md:59-71

VERIFIED The work action is an orchestrator, not a fixed CI graph. It selects dependency-ready work, claims the REQ, chooses a triage route, implements, qualifies, tests, reviews, archives, and commits; holding states and explicit targeting alter selection without inventing another state store. work.md:118-140

VERIFIED Parallelism changes the build phase, not ownership. Auto-wave dispatch computes runnable REQs without using write_set; every builder gets a worktree, integration remains serial, and one releaser owns queue transitions, versioning, and the changelog. work-reference.md:380-407

New architectural center

The Go execution kernel

INFERRED do-work-cli is becoming the deterministic kernel beneath the suite. Its current commands cover distribution mechanics, while its internal runtime, result schema, and Git transaction package are explicitly shaped for later command families. Basis: the main program registers one handler map and the foundation archive describes the seam as the pattern future commands copy.

VERIFIED The public binary is built on demand and atomically replaced. The launcher rebuilds when the binary is absent or older than Go sources, enforces Go 1.26.1, builds to a temporary file, then renames before exec. do-work-cli.sh:23-65

VERIFIED One runtime owns global options, rendering, and exit codes. main.go merges registered handlers into commandruntime; each handler returns a typed CommandResult, whose outcome is mapped to exit status in one place and rendered as text or JSON from the same value. main.go:10-19 · command_runtime.go:41-84 · result_model.go:84-108

VERIFIED Install is a staged, consent-gated, recoverable transaction. The engine resolves the project, obtains and validates the archive, constructs managed candidates, shows diffs, takes one confirmation, writes, verifies, and restores backups on failure or interruption. install_transaction.go:138-189

VERIFIED Update delegates to install inside the same process. It resolves the installed skill, fetches and validates upstream, refuses non-newer versions, then calls the shared install transaction and verifies the resulting installed version. update_transaction.go:51-166

VERIFIED Shell remains the stable public surface, not the source of transactional truth. The root installer maps its legacy arguments to install-suite; the installed updater maps its legacy entry point to update-suite. installer launcher:60-82 · updater launcher:23-33

VERIFIED The manifest remains a closed four-module contract. suitemanifest owns the required source→destination map and validates the suite version plus each package before installation. suite_manifest.go:18-93

VERIFIED Managed text and settings now have typed owners. managedsection performs marker-bounded byte replacement and reserved-Just-name checks; settingshooks decodes JSON into an order-preserving object model and composes hooks without a jq/Python branch. managed_section.go:59-137 · settings_hooks.go:28-56

VERIFIED Archive fetching preserves transport semantics. HTTP publication still uses the atomic download primitive, while Git fallback derives the requested branch and archive prefix from the canonical tarball URL rather than silently archiving default HEAD. archive_fetch.go:75-130

Separate compiled application

The board remains a projection over the file model

VERIFIED queue-kanban is a separate Go program with an embedded browser frontend. Its hand-written dispatcher owns summary, generation, serving, allocation, version-line updates, verification, clock, and frontmatter commands. queue-kanban main.go:58-88

VERIFIED The live server caches parsed state, not time. An unchanged mtime fingerprint reuses the board model but refreshes generation time, open spans, the now-line, and forecasts from one captured instant; a changed tree goes through the full build path. serve.go:330-367

VERIFIED The board still has exactly three narrow write surfaces. Testing mutates its own fields and testers file; next-version rewrites one version line; next-req creates one reservation marker. No board command writes pipeline status or the changelog. queue-kanban main.go:49-54

How the design stays coherent

Tests, primes, decisions, dogfooding

VERIFIED The canonical gate now spans three Go modules. After ShellCheck, gofmt, and the aggregate contract suite, it vets and tests queue-kanban, do-work-cli, and audit-metrics; browser and JavaScript lanes run conditionally and disclose skips. maintainer-verify.sh:446-549

VERIFIED Maintainer context is lazy and domain-owned. Three prime files cover action files, the board, and prescribed shell; each points to a separate lessons satellite so operational history can grow without bloating the prime. CLAUDE.md:66-72 · prime-action-files.md:1-11

VERIFIED The four-skill split is a recorded decision, not folder happenstance. ADR-019 assigns queue lifecycle, board, knowledge, and toolbox ownership, fixes the manifest grammar, and defines update as all-or-recover rather than claiming cross-directory filesystem atomicity. ADR-019:33-61
