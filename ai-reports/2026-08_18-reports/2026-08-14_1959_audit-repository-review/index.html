01P1 README understates install and implementation write boundaries impact 4trivial effort

Claim

The public README says the skill only creates files inside do-work/, while install/update also manage four .claude/skills/ trees and consented Just/settings sections; active REQs may write project paths declared in Scope.

Exact instances

  • README.md lines 24–31 and 158 at the audited SHA
  • skills/do-work/actions/work.md lines 357–365

Why it matters

Adopters make a trust decision before installation. An absolute safety claim that excludes legitimate managed and scoped writes is user-visible, even though the underlying writes are consented.

Remedy. State three boundaries: reviewed managed install paths, durable queue state under do-work/, and project-source writes only during explicitly invoked REQ work within declared Scope. No new checker is justified.

02P2 Public work and schema vocabularies drift while suites stay green impact 3normal effort

Claim

The work guide advertises three aliases the first-match router cannot dispatch; short workflow glosses omit canonical fields/statuses; the board accepts two testing-status aliases absent from the schema table.

Exact instances

  • work-guide.md: begin, execute, build
  • SKILL.md: the actual route alias list
  • work.md and work-reference.md: stale schema glosses
  • testing.go: two runtime-only aliases

Why it matters

These are green-suite mismatches at public vocabulary seams. Users can follow documented words that route elsewhere, and maintainers can evolve the schema table independently of accepted runtime values.

Remedy. Restore the three aliases, keep one public list compared with the router, correct the schema summaries, and enforce bidirectional parity at the work-guide/router and testing-schema/normalizer seams.

03P2 Static board generation can publish a mixed three-file bundle impact 3normal effort

Claim

generateStaticSite writes board-data.js, board-markdown.js, and index.html directly in sequence. A forced second-write failure leaves new rendered data beside old copy payload and shell.

Exact instances

  • generate.go: three sequential os.WriteFile calls
  • generate_test.go: success-only publication call

Why it matters

The output is a shareable static artifact. Mixed-generation files can present internally inconsistent queue data after the generator correctly exits non-zero.

04P2 Live board origin checks have no trusted Host anchor impact 3normal effort

Claim

Exact instances

  • testing_test.go: matching request-controlled Origin and Host

Why it matters

The documented hostile-page defense is anchored only to request-controlled authority values. Peer, content-type, path, and write-scope controls remain valuable, but do not establish the configured listener identity.

Decisions before implementation

Two ideas need a choice, not a ticket yet.

The validation pass preserved these trade-offs under Discuss. Capturing them now would pretend the evidence already chose a direction.

Extract frontend state only after the behavior gate.

A separate board-state.js might reduce brace scraping and fake-DOM setup, but it would not simplify the two highest-CCN DOM functions and could add more assembly surface.

Default: improve executable probes in place. Spike extraction only on a relevant change and only if zero-network file:// output is preserved while net surface falls.

Adopt hosted Linux CI only as an explicit ownership decision.

A Linux lane would exercise case-sensitive portability, but also introduces action versions, runner images, permissions, tool installation, and workflow maintenance.

Default: land the canonical local gate first. If CI is chosen, use one least-privilege Ubuntu lane that invokes only that script—no matrix or duplicate command list.
