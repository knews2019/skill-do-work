## Reading the measurements

- Wall is command elapsed time via perf_counter. CPU is the delta in reaped child user and system resource usage, including descendant usage accounted through waits. It is neither host utilization nor per-executable attribution. CPU/wall is a ratio of accounted CPU seconds to elapsed seconds and can exceed 1 under parallel work. Wall minus CPU is not a measurement of I/O or process startup.
- Go accumulated time sums elapsed values from top-level test pass/fail events, excluding slash-named subtests and package events. It is neither CPU nor package or whole-gate wall time and can overlap across tests. n/a means unavailable, not zero. Reused-stage is its own selection/condition with no matched cold or warm sample.
- The TSV reports timings in seconds to three decimal places. Use the recorded total CPU field. Component rounding can cause a 0.001 s discrepancy (inventory cold line 12 has 0.712 + 0.904 versus 1.615 recorded). Medians of separately measured components need not add to the median total. Archive ± figures use max minus min, not half-range, confidence intervals or standard deviation.
- An intercepted count is a PATH shim hit per measured command invocation, including the top-level command if it resolves through a shim. The wrapper logs and execs the resolved real executable. Coverage is limited to available shims for git, go, bash, python3, shellcheck, shasum, find and curl. Absolute paths, unshimmed tools such as grep, shell builtins, and internal threads are outside that coverage. Counts do not establish time spent by each tool.
- The frozen runner's cold branch calls go clean -testcache, while the Go selections already use -count=1. Cold and warm identify the recorded groups, without proof of a cold Go build cache. The TSV does not encode worktree dirt or complete environment provenance. The R1 review independently reproduced a SIGTERM status discrepancy (JSON -15, shell 241, conventional shell status 143). This run's zero statuses give no signal-handling evidence.
