### Findings

**Important:**
- F1 `skills/do-work/actions/work.md:370` (Step 7, How to run it) decides "last" from "the run manifest shows every other member of this REQ's wave finalized or set aside". The manifest contract records only the landed status of the hand-back (`skills/do-work/actions/work-reference.md:480` manifest row: "handback file, landed status, held dispatch instant"; `skills/do-work/crew-members/background-agents.md:50-54` and its Manifest Format: `pending`/`done`). No step in work.md writes finalized or set-aside to a manifest row (the only manifest writes are at lines 288 and 296: the hand-back path and the held dispatch instant). Set-aside is a recovery finalization record (`FINALIZATION-SET-ASIDE`, work-reference.md:812), not a manifest state. This run's manifest says "finalized by the integrator" only as free text the coordinator chose to add. An orchestrator that follows the contract sees "landed" for every member and either never passes the fact (sweep silently skipped) or treats "landed" as "finalized" (passes it too early, before the last member merged). Fix direction: take wave membership from the manifest and finalization state from the archive or the recovery finalization records, or add a finalized/set-aside status to the manifest row contract. — impact-rule-change → report only

**Minor:**
