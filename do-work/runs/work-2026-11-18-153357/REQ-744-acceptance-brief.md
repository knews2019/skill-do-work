# Report writer acceptance cases

Run the writer on a disposable consumer after REQ-743 has been finalized. These inputs are test fixtures, not production measurements. Use the actual gallery command, shipped presets and report-writer instructions.

1. Provide a request-completion table for two equal-duration windows. Window A had 100 completed requests and 90 successful ones. Window B had 200 completed requests and 160 successful ones. Ask “We served more successful requests. Did the success rate improve?” The count rises from 90 to 160 while the rate falls from 90% to 80%. Both chart titles must identify their own units. Both need the same windows. A checkable verdict makes verdict-with-checks a plausible runner-up.
2. Inspect the generated page head, the explanation of the gallery choice in the handback, and every closing prompt. Parse the displayed command as shell arguments and check the preset against the current bundle and installed presets. Exercise the directed prompt through the existing prepare path in the disposable repo. The writer prints the prompt without launching a second model.
3. Use a simple text-only change, such as correcting the spelling of the label “Account settings,” with no competing quantities, audit judgment, component series or cycle. Check the none marker and the existing alternate layout and teaching suggestions.
4. Verify the ordinary, proposal/root-cause and revise paths all reach the matching rule. A second opinion on an existing page must still follow its existing direction.
