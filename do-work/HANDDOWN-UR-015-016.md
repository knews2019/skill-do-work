### 3. Mechanical traps hit this session

- **`git mv` stages content at move time.** REQ-077's first commit captured the *pre-edit* archived
  REQ, because the appends made after the move were never `git add`ed. It had to be amended. Always
  `git add` the archived REQ explicitly, after the last append, before committing.
- **`git add` aborts the whole invocation on one bad pathspec.** The same commit staged nothing
  because one path in the list no longer existed. Check `git status --porcelain` after staging, before
  committing.
- **Reproducing a suite regression needs `git show HEAD:<path>`, not `git archive`.** `_dev/`,
  `CLAUDE.md` and `.gitattributes` are all export-ignored, so a tarball of `HEAD` has no test suite
  and the suite's own export-ignore assertions fail against it. Writing HEAD's copy to
  `_dev/tests/.old-suite.sh` works, because `repo_root` derives from `BASH_SOURCE`.
- **Shipped files must never cite `CLAUDE.md`.** A first draft of REQ-078's Timestamp rule did; it was
  caught by grepping the touched files, not by the suite (the existing guard greps different idioms).
  REQ-088 is a queued pending-answers REQ about an older instance of the same thing.
