- `skills/do-work/tools/do-work-cli/internal/corehelpers/inventory.go`:
  `readInventory(repositoryRoot string)` currently calls `gitOutput(...)` to obtain `status --porcelain=v1 --untracked-files=all -z` raw bytes, and then immediately processes records in-line. We can cleanly extract `parseInventoryBytes(output []byte) ([]inventoryRow, error)` so byte parsing is completely decoupled from Git acquisition.
- `skills/do-work/tools/do-work-cli/internal/corehelpers/inventory_test.go`:
  `TestInventoryMatchesRetainedPorcelainXYMatrix` (45 cases), `TestInventoryMatchesRetainedSecretOriginAndAmbiguityMatrix` (10 cases), and `TestInventoryDifferentialComparatorRejectsClassPathAndOrderMutations` (1 case) currently invoke `runSyntheticInventoryPair`, which for each test case creates temp directories, writes a fake git shell script, and spawns the compiled `do-work-cli` binary with `DO_WORK_COMPATIBILITY_SHIM=1` while simultaneously executing `readInventory` in-process with `PATH` overridden to call the fake git script. In effect, it runs the identical Go code against itself via 56 subprocesses.
- Tracing the retained-command path:
  `runRetainedInventory` with `syntheticStatus != nil` ran `do-work-cli --repo-root <repo> --format text uncommitted-inventory`, which calls `handleInventory` -> `readInventory`. This was purely a self-comparison of the same Go parser against itself across a serialization boundary.
  Meanwhile, `runRetainedInventory(t, repository, nil)` (used in `TestInventoryStagedAdditionDeletedFromWorktreeIsDeletion`) actually runs the shipped `checks/uncommitted-inventory.sh` script end-to-end against a real Git repository, providing true launcher and integration coverage.
- Coverage preservation & improvements:
  - Replace the 56 subprocess calls with direct in-process calls to `parseInventoryBytes(statusBytes)`.
  - Explicitly assert expected rows and findings in `TestInventoryMatchesRetainedPorcelainXYMatrix` and `TestInventoryMatchesRetainedSecretOriginAndAmbiguityMatrix`.
  - Cover error cases directly in-process: short porcelain records (`< 4` bytes) and missing rename origins (odd record count / empty record for `RC`).
  - Keep real Git integration tests intact: `TestInventoryStagedAdditionDeletedFromWorktreeIsDeletion`, `TestInventoryDropsUntrackedHiddenFilesUnderDoWork`, and `TestInventoryPreservesSecretRenameOriginAndQuarantinesAmbiguousAdds`.
  - Remove the now-redundant `runSyntheticInventoryPair` and `fakeGit` plumbing.

## Decisions

- **D1 Decouple Git acquisition and porcelain byte parsing via `parseInventoryBytes`:** `readInventory` executes `git status --porcelain=v1 --untracked-files=all -z` and passes the byte output to `parseInventoryBytes`. This clean separation allows pure-data inventory cases to run completely in-process without spawning Git or helper binaries.
- **D2 Elimination of redundant 56-subprocess self-comparison loop:** `runSyntheticInventoryPair` spawned `do-work-cli uncommitted-inventory` in a subprocess with a fake Git script and compared its tab-delimited output against `readInventory` called in-process (the exact same Go implementation compared to itself). Eliminating this subprocess loop removes 56 process spawns per test run while preserving 100% of the input coverage and assertions.
- **D3 Dedicated in-process contract coverage (`TestParseInventoryBytesContract`):** Explicit test cases cover: short records (`< 4` bytes returning "short porcelain record"), missing rename origins (returning "rename origin missing"), record ordering preservation, `.DS_Store` / swapfile metadata pruning under `do-work/`, and cross-row secret promotion (promoting `A` to `X` when secrets are present while leaving `M`/`D` unchanged).
- **D4 Preservation of real Git and end-to-end launcher tests:** `TestInventoryStagedAdditionDeletedFromWorktreeIsDeletion` and `TestInventoryPreservesSecretRenameOriginAndQuarantinesAmbiguousAdds` retain real Git fixture operations and execute the real launcher script `checks/uncommitted-inventory.sh` end-to-end via `runRetainedInventory`, verifying actual process boundaries, signal safety, and compatibility text formatting.

## Lessons Learned

**What worked:**
- Decoupling data parsing from I/O (`parseInventoryBytes` vs `gitOutput`): pure data parsing can be exhaustively tested in microseconds without touching the filesystem or invoking external processes.
- Identifying and eliminating self-comparisons: testing Go code against the exact same Go code via a serialized subprocess provided zero independent differential value and imposed a massive 56-subprocess penalty.
- Preserving real-Git end-to-end checks: keeping real Git and launcher checks in `TestInventoryStagedAdditionDeletedFromWorktreeIsDeletion` and `TestInventoryPreservesSecretRenameOriginAndQuarantinesAmbiguousAdds` ensures genuine integration coverage is preserved.

**What didn't:**
- Relying on subprocesses with fake shell scripts in unit tests introduces excessive process spawn overhead and fragile PATH/environment overrides.

**Worth knowing:**
- In-process testing of byte transformations is orders of magnitude faster (0.00s vs 8.8s) while allowing simpler, more direct assertions on edge cases (such as malformed NUL records and truncated origin entries).
