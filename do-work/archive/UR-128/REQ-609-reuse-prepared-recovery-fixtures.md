## Implementation Summary

1. **Declared Singleton Templates in `internal/finalization` (`finalization_commands_test.go`):**
   - Declared `semanticLegacyTemplateOnce`, `semanticLegacyTemplateRoot`, and `semanticLegacyOwnedPaths`.
   - Declared `plannedFinalizationTemplateOnce`, `plannedFinalizationTemplateRoot`, `plannedFinalizationSeedCommit`, `plannedFinalizationRequestSHA256`, and `plannedFinalizationCheckpointSHA256`.
   - Implemented thread-safe lazy initializers `initSemanticLegacyTemplate(t testing.TB)` and `initPlannedFinalizationTemplate(t testing.TB)` that initialize from `finalizationRepositoryTemplate` via `os.CopyFS` and build the committed/interrupted state once per test run.
   - Updated `TestMain` to safely clean up `semanticLegacyTemplateRoot` and `plannedFinalizationTemplateRoot` if non-empty upon test completion.
   - Generalized helper functions (`runFinalizationGit`, `writeFinalizationFile`, `readFinalizationFile`, `digestFile`, `newFinalizationRepository`) to accept `testing.TB` instead of `*testing.T`.

2. **Prepared Recovery State Reuse (`finalization_recovery_test.go`):**
   - Extracted `buildSemanticLegacyFixture(t testing.TB, repositoryRoot string) semanticLegacyFixture` preserving exact original behavior for dynamically configured fixtures.
   - Updated `seedSemanticLegacyTail(t *testing.T, repositoryRoot string) semanticLegacyFixture`: For clean repositories (holding only `.git`), replaces the initial repo with an independent `os.CopyFS` clone of `semanticLegacyTemplateRoot` and returns an independent copy of `semanticLegacyOwnedPaths`. Falls back to `buildSemanticLegacyFixture` if callers pre-populated custom files in `repositoryRoot`.
   - Updated `seedPlannedFinalization(t *testing.T, provenanceMode string) (string, string)`: Allocates an isolated `t.TempDir()`, copies `plannedFinalizationTemplateRoot` via `os.CopyFS`, and synthesizes `manifest.json` using cached digests and seed commit without repetitive Git subprocesses.

3. **Explicit Isolation & Defect Rejection Verification (`finalization_recovery_test.go`):**
   - Added `TestPreparedRecoveryTemplateIsolation`: Validates that heavily mutating one copy (modifying tracked files, adding new files, committing changes, deleting files) leaves other copies and the underlying template completely untouched across both semantic legacy and planned finalization fixtures.

## Decisions

- **Preserve Dynamic Fallback for Pre-populated Callers:** While 10 calls to `seedSemanticLegacyTail` use a clean repository, calls in `finalization_req512_test.go` and `finalization_req565_test.go` pre-write custom manifests before seeding. Checking whether the repository contains non-`.git` entries allows full optimization for clean cases while maintaining 100% backward compatibility without modifying unlisted test files.
- **Lazy Initialization via `sync.Once`:** Templates are constructed on demand rather than unconditionally in `TestMain`, ensuring tests targeting unrelated subpackages or single tests do not pay construction overhead.
- **Copying via `os.CopyFS` into Fresh `t.TempDir()`:** Preserves full filesystem, index, HEAD, and Git recovery semantics without sharing any mutable state or precomputing outcomes.

## Lessons Learned

- Removing `.git` before `os.CopyFS` is essential when copying a populated Git repository onto a previously initialized template destination; Git object files are marked read-only (0444), which causes `os.CopyFS` to fail with `EACCES` when attempting to overwrite existing destination files. Removing the destination `.git` directory allows fresh file creation without permission errors.
