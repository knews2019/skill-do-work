### Measurement Observations & Removable Work Ranking
1. **A3 (Inventory):** Significant process spawn churn (`git` and `do-work-cli`) across 45 synthetic status combinations. In-process byte testing directly cuts this overhead.
2. **A2 (Heavy CLI Build):** Calling `buildTestCLIBinary` 3 times inside integration tests invokes redundant Go builds and links. Caching/sharing one compiled binary saves multiple compilation seconds.
3. **A4 (Finalization Recovery):** Repeated Git repository construction (`seedSemanticLegacyTail`) spends seconds creating history from scratch. Pre-baking template states saves repetitive git commits.

## Lessons Learned

**What worked:**
- Using `resource.getrusage(RUSAGE_CHILDREN)` in Python to cleanly aggregate process hierarchy CPU metrics without third-party dependencies or elevated OS permissions.
- Temporary PATH shimming to count toolchain invocations without modifying application code or test assertions.
- Distinguishing accumulated test elapsed time from package wall clock time using Go test JSON output.

**What didn't:**
- Sourcing duration logging inside subshells triggers ShellCheck SC2031 warnings when global variables are reassigned in the sourced file; sourcing once at script top-level resolves the issue.

**Worth knowing:**
- `GOMAXPROCS=4` should be fixed when benchmarking multi-threaded Go tests to ensure stable, comparable CPU and wall times across runs.
